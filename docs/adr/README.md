# Architecture Decision Records

Records 0001–0005, 0007, and 0008 are **proposed for the AI RPG Engine implementation baseline**. Record 0006 is accepted as the implementable default ruleset, with provisional numerical values. Record 0009 is accepted for its completed sections only. Record 0010 is accepted: it records the product name, v1 boundaries, initial pack file format, and licensing plan. Owner-supplied constraints are identified separately from design choices. No “accepted” status implies implemented code or completed validation.

| Record | Decision |
| --- | --- |
| [0001](0001-modular-stack.md) | Retain the Angular/Java/PostgreSQL stack and a modular backend |
| [0002](0002-codex-only.md) | Use Codex app-server as the initial AI integration; scope extended by [0020](0020-selectable-narration-runtime.md) (Claude as a selectable alternative) |
| [0003](0003-canonical-transactions.md) | Backend-owned canonical transactions and durable operation receipts |
| [0004](0004-declarative-adventures.md) | Declarative immutable adventure packs and bounded extension points |
| [0005](0005-renewable-memory.md) | Canonical memory independent of renewable AI sessions |
| [0006](0006-original-combat.md) | Original zone-based deterministic combat with constrained AI proposals; accepted as the implementable default, numbers provisional |
| [0007](0007-audience-isolation.md) | Knowledge filtering and role/audience thread isolation |
| [0008](0008-containerized-startup.md) | Containerized packaged installation and root `start.sh`; supersedes the deployment assumptions in 0001 and 0002 |
| [0009](0009-toolchain-baseline.md) | Pinned supported toolchain versions; frontend, backend, build, database, host platform, container image, Compose, and shell sections accepted; the narration runtime image belongs to P01.1 |

| [0011](0011-visual-novel-and-persistent-artwork.md) | Default visual-novel play, editable quick replies, complete graphic kit, persistent character/item artwork and bounded runtime image generation; accepted design, implementation pending |
| [0012](0012-adventure-workspace-isolation.md) | Independent adventure specifications, campaigns and media directories with explicit identity/isolation; accepted design, implementation pending |

| [0015](0015-bilingual-first-release.md) | English-default and first-class Italian from MVP, small locale model, compiled UI variants and direct selected-language narration; supersedes English-only assumption |

| [0017](0017-bounded-pack-semantics.md) | Static bounded expressions/effects, dependency cycles, SemVer compatibility, hash conflicts and a deterministic generation gate for fixed author constraints; implemented in P04.3, runtime callers pending |
| [0018](0018-protected-pack-registration.md) | Bounded directory/ZIP staging, media headers, transactional original-byte storage and serialized immutable sealing; implemented in P04.4, import UI and decoding pending |
| [0019](0019-local-campaign-admission.md) | Opt-in configured-owner local admission, bounded session/CSRF proofs and strict atomic campaign creation; implemented in P06.1 |
| [0020](0020-selectable-narration-runtime.md) | Selectable narration runtime: Codex by default, Claude Code as the alternative, one at a time, no automatic failover; Claude is supported only after P20 evidence and a recorded terms review; accepted design, implementation pending |
| [0021](0021-inference-backends-and-model-selection.md) | Closed protocol set with open models and endpoints; four owner-assigned slots (light, standard, deliberate text and image); free local text and image backends with recommended defaults for the reference host; API-key gateway; hardware advisor; shared GPU admission; accepted design, implementation pending |
| [0022](0022-optional-speech-input.md) | Optional EN/IT STT and hands-free exploration/combat, explicit microphone control, voice-only review/confirmation, normal command authority, echo/privacy/resource gates; accepted design, implementation/backend qualification pending |
| [0023](0023-character-rules-and-equipment-constraints.md) | Character rule vocabularies per creation-profile pack, pure derived statistics, stacking conditions, explicit rarity tiers and combined slot/hand/capacity equipment constraints with no artwork-derived mechanics; implemented in P10.1 |
| [0024](0024-atomic-item-commands-and-source-linked-creation.md) | Atomic use, equip, unequip, give and trade commands over a conservation-proved item plan, identity-preserving transfers with merging, a pack item use contract and value, and an append-only creation ledger linking every created unit to its operation, event and source; implemented in P10.2 |
| [0025](0025-quest-lifecycle-objective-predicates-and-one-time-rewards.md) | Pure quest transition engine over committed facts: derived discovery, player accept/suspend/resume, sticky objectives, ordered outcomes, cascades and rewards in one commit, hidden background quests, and one-time reward settlement guarded by terminal immutability, a unique settlement per quest and the shared creation ledger; implemented in P10.3 |
| [0026](0026-bounded-world-clock-travel-duration-and-rest.md) | Bounded world clock moved only by committed commands (one day per operation, a century in total, database-enforced), authored travel minutes on location links, a four-hour legal wait, pack rest policies with a recorded interruption draw, typed condition removal and a `worldTime` quest atom. |
| [0027](0027-player-panels-and-journal-projection.md) | One read-only repeatable-read projection for the player panels and journal: clock, effective character sheet, conditions, inventory with worn slots, engine-state quests (hidden ones withheld until they end), typed knowledge with stances and promises, and a cursor-paged public event history worded in the campaign language; names from public pack text only; implemented in P10.5 |
| [0028](0028-encounter-lifecycle-frozen-profiles-and-zone-graph.md) | Encounter lifecycle state machine enforced in code and database, per-adventure combat profiles as a fixed kernel plus bounded parameters around AI RPG Skirmish, pack encounter templates with a zone graph, explicit statistics and predicate objectives, an explicit `ENGAGE` entry that freezes everything and resolves nothing, and the opening-action policy; implemented in P11.1 |
| [0029](0029-initiative-rounds-activations-and-bounded-combat-dialogue.md) | Initiative rolled once as its own recorded operation, one pure initiative-round scheduler that stops only at the player's decision, activations with expiring action points and round time, five tactical intentions legal only in encounter mode, legal addressing by range, one bounded speech-only utterance per activation and declared, priced social and scene actions, with V23 database guards; implemented in P11.2 |
| [0030](0030-attacks-defense-damage-and-healing-with-recorded-draws.md) | Pure attack, defense, damage and healing arithmetic; attacks frozen from pack data at entry; fixed draw order with a public outcome and an internal calculation; Guard stance, ammunition as item units, opening strikes resolved once at their slot, a small interim tactic for non-player participants, and V24 Health guards. |

When a decision changes, preserve this record and create a superseding one with rationale, compatibility implications, and verification. Do not retroactively edit historical status to make a previous decision disappear.
