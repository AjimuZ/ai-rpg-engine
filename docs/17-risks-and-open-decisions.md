# Risks and Open Decisions

P06.5's persisted library GETs expose only owner-authorized public workspace
metadata and never persist an active selection. Guarding the entire adventure
subtree closes the admission gap before further routes are introduced. This
checkpoint now includes opt-in derived specification/authored-media folders, but
not browser binding; preview draft isolation is still distinct from real workspace
recovery. Projection duplicates disk usage and verifies every sealed revision at
startup. Post-commit projection failure preserves registered content and requires
storage repair/retry. Roots must be private and quiescent; static-link rejection
does not protect against a hostile local process swapping ancestors. Failed private
staging folders require offline operator cleanup, never automatic deletion.
The browser library is now bound read-only, and stale replies are aborted when
switching adventures. However, packaged reload of `/saved/...` is not yet allowlisted.
QA-33 remains open for memory, artwork, owner-wide job limits and combined
restart/restore evidence, which come from packages that already depend on P06.
The roadmap therefore needs an owner decision to split this evidence into a later task. Later pages are fresh snapshots, so
concurrent additions may require refreshing the library from its first page.

P06.2 introduces explicit public DTOs and player-audience fact/quest storage;
all 296 packaged backend tests pass on PostgreSQL 18.6, including eleven real
HTTP tests, concurrent snapshot consistency and separate-JVM public-view restart.
It deliberately withholds raw pending decisions,
NPCs, pack bodies and planning artifacts. Learned abilities do not imply legal
current actions. P06.3 adds only a versioned starting-decision allowlist and
localized public entrypoint projection; unsupported decisions remain private and
no choices are synthesized. Missing translations explicitly fall back to the
source locale. All 299 packaged backend tests pass on 25 October 2026, including
EN/IT, fallback, authored revision pinning and restart; browser delivery remains
unimplemented. Reveal/progression writers, further decision types, frontend
API binding and full QA-33 media/draft/restore isolation remain later tasks.

P06.4 exact consultations are deterministic server reads, not a browser composer
integration or durable transcript store. Only documented English/Italian whole
aliases route locally; other text fails closed without runtime interpretation.
Detached passages carry committed source scope and are safe to repeat without
world writes. A future transcript writer still needs its own delivery identity,
deduplication and retention policy, independently of canonical commits. All 300
packaged backend tests pass on 25 October 2026, including progressed/depleted-save
no-write comparisons, scope rejection and consultation restart reconstruction.

P02.3 packaging evidence (23 October 2026): pinned engine/runtime images and root
Compose isolate networks/mounts; only engine/PostgreSQL receive the database
file secret. Account-free HTTP, IPC, secret consumption and neutral preservation
across recreation of all three containers pass on Windows Docker Desktop Linux
containers. Engine-only content/assets storage is reserved, not a pack/asset
pipeline. This does not close live account/tool containment, canonical campaign
recovery, launcher readiness or QA-28. ADR 0009 permits the current Java pins for
development; refreshing Java remains a release gate. Secret initialization and
host permission hardening remain P02.6 work; file mounts are not encrypted.
Native Linux-host UID readability remains unverified. Ordinary Spring overrides
retain their standard precedence; configtree is not a secret manager.


P06.1 has verified atomic creation and an opt-in local HTTP
adapter with configured owner/origin and bounded session/CSRF admission. All 290
packaged backend tests pass on PostgreSQL 18.6. Separate-JVM restart
acceptance now preserves both genre campaigns and rejects old browser sessions.
Dependency mechanics reload a bounded sealed
closure; conflicting versions of one pack ID are rejected rather than aliased.
Browser reload/projection acceptance remains later P06/P05 integration work.
Existing campaigns receive no invented character-state backfill.

## 1. Risk register

Partial P05.6 reduces translation drift for the 218 marked local-preview
messages through source freshness, exact ID and placeholder checks and separate
browser-reviewed EN/IT builds. Local recovery guidance, validation, unsaved receipts
and accessible names are reviewed; real transport errors and receipts remain open.
Review variants now persist device language and validate reading/draft state before
reload, restoring equivalent-control focus and invalidating old callbacks/replies.
Unsaved/conflicting drafts, unresolved recovery and real campaign contexts block
reload. They do not establish durable operation/cursor reconciliation. Both
variants now enter the jar/container with finite route handling and a root
device-preference selector; production resource/recreation checks cover both trees.
Real API localization remains a transport gate. Resource review does not establish independent bilingual playtest
acceptance or complete QA-35.

P05.6 scheduling audit (24 October 2026): real campaign reload, API localization
and source-pack fallback depend on the still-proposed P06/P07 browser transports.
P06 also lists P05 as a dependency; requiring full P05.6 acceptance before any
P06 work would deadlock delivery. Schedule prerequisite campaign/projection and
operation/stream work using the delivered interface contracts, then resume the
[P05.6 integration evidence matrix](29-localization.md#p056-integration-prerequisites-24-october-2026-audit).
Do not treat preview receipts or internal persistence tests as transport evidence.
Independent bilingual and screen-reader reviews remain human acceptance gates.

P05.5 reduces local UI asset/rights risk with original editable MIT SVG/CSS,
a complete public source inventory and shipped notice, without external art/font
dependencies. Browser-reviewed control/meter/frame fallbacks preserve text,
numeric labels, keyboard access and forced-colour/reduced-motion use. This covers
the local graphic kit only; it does not settle runtime generation capability,
campaign identity/rights, bilingual review or release accessibility gates.

P04.1–P04.4 now separate parsing, semantic compilation, protected staging and
transactional admission. `ParsedPack`/`CompiledPack` alone are not admitted
revisions. ZIP bytes never extract to disk; database seals prevent ordinary
mutation and late insertion, including concurrent writers. Directory imports
require owner-controlled, quiescent source trees: intermediate-directory races
against another local process are not excluded by portable path APIs. Media
signature/dimension checks do not prove codec validity, decoded memory bounds or
rights. No serving/import endpoint exists; decoder/frame/duration limits and
request concurrency budgets must precede those APIs. Original bytes live in
PostgreSQL, increasing database/backup size; moving them to managed folders later
requires a coherent migration. See [ADR 0018](adr/0018-protected-pack-registration.md).
Ruleset 1.0.0 and its descriptor digest remain provisional until P07. Reachability
is a heuristic, and no runtime caller enforces the generation gate before P10/P12.
P04.5 adds standalone fantasy/salvage fixtures and PostgreSQL checks for unchanged
directory/ZIP import, sealed byte preservation and invalid-reference rollback.
Optional modules remain disabled because no runtime exists. P04.6 validates EN/IT
text catalogs and source-owned policies, with explicit source fallback and sealed
coverage. It cannot prove prose fidelity or authorize an audience: future consumers
must filter the source owner/field before catalog lookup. Bilingual human playtest,
localized UI/narration, playable two-genre acceptance and full workspace isolation
remain later gates; successful fixture import does not establish those exits.

P03.6 verifies scoped durable jobs, complete snapshot manifests, fenced admission,
query-epoch races, cancellation/restart metadata and generation retirement on restore.
These remain internal foundations: every future gameplay writer must identify all
affected query scopes, or phantom protection is incomplete. Non-query semantic
dependencies fail closed until P08.7. Attempt/usage persistence does not enforce
installation-wide quotas or fairness, and persisted cancellation is not proof that
the runtime stopped; explicit stop confirmation is required before retry. P07/P08
must establish those boundaries before enabling scheduling or plan consumption.
The V6 backup remains database-only, with all old writers/workers stopped during
single-installation recovery; full content/assets and identity-remapping restore
remain P16. No completed QA-36/37 or narrative benefit is implied.

P07.6 adds typed row-version dependencies, the transactional scope/content/author gate
and plan activation only through ordinary canonical commands. Remaining risks: a later
writer (items and quests at P10; P09.1 knowledge writers comply) that neither steps the row versions it
changes nor bumps the affected query scopes would leave plans undetectably stale, so each
such writer needs the same epoch/version evidence in its tests; predicates and constraint
rows still fail closed until P08.7; and activation is at most once per artifact branch,
not per domain settlement, so a refined plan version can offer an equivalent branch again
until pending-event settlement keys arrive (P10).

P08.7 adds the quest-plan contract, selective narrowing and bounded replanning with
deterministic evidence only. Open risks:

- Narrative value, false-invalidation rates and preparation waste are unmeasured. The
  AP-12 live comparison is deferred to P14 (optional) and P18.6, so planning stays off by
  default.
- An observed-only read (one the plan never references) guards nothing. Plan prose that
  names such an entity without a predicate can go stale silently. This is accepted because
  plan prose is private, never canon and never narrated; actual use rechecks current state.
- Location membership has no query epoch yet, so an actor arriving after capture is not
  detected as a phantom.
- Branch predicates that read the holder's own row invalidate their branches whenever the
  player moves.
- No consumer builds commands from plans yet (P10).

P09.1 adds typed claims, beliefs, last known locations and commitments. Open risks:

- Two knowledge stores exist until P10.5: the free-text `campaign_known_fact` projection (no
  writer, still read by the player projection and the planner's `fact-known-to` predicate) and
  the typed records. Since P09.2 context assembly reads only the typed records. P10.5 moves the
  panel and retires the old table, which needs a migration decision.
- Observation is player-only and refreshes every co-present sighting on every action. That
  bumps `sightings:<player>` often, so a future reader that records this scope will see
  frequent staleness. More than 64 co-present actors records no observation at all.
- Nothing yet writes claims, beliefs or commitments from play: the `reveal` effect, plan
  consumers and dialogue-made promises are P10/P12/P15. Until then reveals and commitments
  exist only through trusted internal operations and tests.
- Content references (`location:`, `definition:`) are checked for form, not against the pinned
  closure. A trusted resolver that writes a dangling id creates a claim that reveals nothing.

P03.4 adds durable same-operation random reuse and pinned HMAC-SHA-256 v1 identity.
Private campaign seeds are trusted database/backup material, never runtime context.
Reservation survives failed/cancelled canonical work, but future command policy must
still prevent equivalent unresolved actions from using fresh operation IDs to fish
for rerolls. P03.5 adds a database-only backup and leases/fences; startup recovery assumes one
local installation. Seed/draw ledgers
must be preserved together and protocol changes must retain old replay support.

## 2. Open decisions with safe working defaults

P01.7 explicitly selects [serialized inference](../tools/runtime_probe/CONCURRENCY.md),
one active turn installation-wide. Its bounded scripted routing/cancellation
evidence does not establish live simultaneity, headroom, service priority or
quota behavior. P08.6 implements production priority, fairness, quotas and
recovery with deterministic QA-37 evidence and keeps the increase gate closed
(`max-active` above 1 fails startup); the live QA-37 part and the P01 live isolation
recheck are still open.

| Visual authoring editor | Deferred beyond v1 | Separate initiative | File-contract stability and author feedback |

## 3. Scope-change procedure

A change affecting authority, persistence, content compatibility, AI provider, combat scheduler, or hosting requires an ADR update and revised acceptance/roadmap mapping. A new pack's names, artwork, ordinary items, or supported abilities do not require rewriting engine architecture.

Record why a change is needed, what current behavior demonstrates the problem, which compatibility boundaries change, migration/recovery impact, and how to verify it. Do not silently adopt a source project's superseded decision merely because an old paragraph still contains it.
