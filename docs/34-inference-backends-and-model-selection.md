# Inference Backends and Model Selection

## 1. Status and scope

**Design specification, partly implemented.** [ADR 0021](adr/0021-inference-backends-and-model-selection.md) adds free local models, API-key backends and owner-chosen model slots to the engine. Package P21 delivers it, and until it records measurements every speed, memory and quality figure is an estimate or an upper bound.

At that date no slot setting, gateway or image worker existed.

Implemented in P21.4-C.1.2.2.2 (1 November 2026, task still open): behind the same switch, `ImageAdmission` runs an image request through the executor as a stepped job and turns what cannot run into a fixed failure, for the caller's catalog art ([section 10](#p214-c1222-image-requests-through-the-lease-executor)). This is tested with a recording image port and scripted workers only. No code calls it yet. The goal is to **recommend** a good default for the detected hardware while leaving the owner **maximum freedom** to choose any other model. The engine therefore fixes the protocols it can speak and leaves the models and endpoints open. It does not fix the models.

This document covers the backends, slots, catalog, local servers, gateway and shared admission. It builds on [Claude runtime integration](33-claude-runtime-integration.md) and [Codex integration](06-codex-integration.md) for the agent runtimes. It also builds on [local speech](30-local-speech-synthesis.md) for the shared GPU policy and on [presentation assets](23-presentation-assets.md) for image jobs.

## 3. Reference host and recommended defaults

VRAM budget: 12,282 MiB minus about 1,270 MiB for the desktop minus a 1 GiB safety margin leaves roughly 10 GiB for one model plus its context and buffers. The 12B build has 6.5 GiB of weights. A decode upper bound is bandwidth divided by weight size: 504 ÷ 6.98 ≈ **72 tokens/s** (estimate, an unreachable ceiling). Measured on 1 November 2026 (P21.2-D, one request, thinking on): 44.3 tokens/s for the 12B build, which is below that ceiling. Details and limits are in [section 7](#p212-host-measurements).

| Slot | Recommended default | Why | Alternatives |
| --- | --- | --- | --- |
| `text.standard` | Gemma 4 12B-it QAT Q4_0 (Google GGUF) | Apache-2.0; official 4-bit training build; fits with room for context; 256K window; system role, tool-use format and thinking mode on the card; strong reported multilingual score | Qwen3.5-9B (community GGUF, to pin in P21.1); any compatible GGUF |
| `text.light` | The same resident model, short outputs, no thinking | Two models do not fit together (7.0 + 3.3 GB plus buffers exceed the free VRAM), and swapping costs seconds | Gemma 4 E2B on CPU if RAM allows; a hosted small model |
| `text.deliberate` | The same model with thinking on and a larger budget | Same reason | An agent runtime or an API model chosen by the owner |
| `image` | WAI-illustrious-SDXL v17.0 (the owner's choice in the predecessor project) | Fits alone in VRAM; anime and fantasy styles; fp16 single file; VAE integrated | Pony Diffusion V6 XL (owner's secondary choice); SDXL base 1.0 as a neutral baseline; the owner's own Forge server |

Expected not to fit this host for local use: Gemma 4 26B-A4B (14.4 GB), Qwen3.6 27B and 35B-A3B. Only the first was loaded (P21.2-D): it ran at 31.9 tokens/s decode with a default context of 4,096 tokens and 11,546 MiB peak VRAM, but whether layers stayed off the GPU was not read, so "workable" is not claimed. The other two were not tried. A 16 GB single-channel memory system makes CPU offload slow and tight. The advisor lists them as "needs more VRAM or RAM" and still allows them.

Presets the advisor can propose for this host (the owner picks):

- **Local-only:** every text slot uses the resident local model, images use the local worker. It is free and offline once the files are fetched.
- **Hybrid:** `light` and `standard` use the local model, `deliberate` uses an agent runtime or an API model.
- **Cloud-first (current default):** Codex for text and the local worker for images, because no agent runtime supplies images.

Expectations to set honestly: a 12B local model is weaker than the agent runtimes at long-range consistency and strict formats. The design absorbs this with constrained decoding, typed validation, one repair and the deterministic receipt fallback. Narration quality in English and Italian is evaluated in P21.6 and is not assumed.

| Protocol adapter | Serves | Class | Notes |
| --- | --- | --- | --- |

| `local` | Text slots | local | Managed llama.cpp server, section 7 |
| `openai-compatible` | Text slots | local or metered | OpenAI's API, hosted providers, or the owner's own server (Ollama, LM Studio, vLLM and similar) through the gateway |
| `anthropic-api` | Text slots | metered | Messages API with the owner's key through the gateway. This is the route Anthropic recommends for products |
| `local-image` | `image` | local | Managed image worker, section 8 |

| `openai-images` | `image` | metered | Hosted images API with the owner's key |

A slot assignment is the backend, a model identifier, parameters (context size, sampling, thinking) and an optional same-class fallback list. The engine sets the effective model and parameters explicitly on every task and records the backend, model, file hash (local) and parameters with each AI task and each generated asset. Capability levels are recorded per model: `schema-enforced` (grammar or native schema output), `prompted-json` (works through validation and repair) and `prose-only` (usable for narration slots that need no structure).

## 5. Catalog and hardware advisor

- **Catalog.** A versioned data file in the repository. Each entry has: id, kind (text or image), source URL and revision, files with size and SHA-256, license identifier and URL, notice and attribution text, requirements (VRAM, RAM, disk, context), languages, capabilities, intended slots, content notes, and a measured profile once P21 records one. Unverified or non-redistributable entries are excluded from defaults.
- **Hardware profile.** The launcher writes `.local/hardware.json` from the GPU driver tool, the operating system and the container engine: GPU, VRAM, RAM and module layout, disk, and whether a container can see the GPU. The owner can read it, and it contains no identifiers beyond hardware models.
- **Advisor rules.** A text model fits when its weights plus the KV cache for the chosen context plus compute buffers stay within free VRAM minus the margin. An image model fits when checkpoint plus activations at the chosen resolution do. The advisor prefers entries with a measured profile, then Apache-2.0, MIT or OpenRAIL-style licenses, then language coverage. It ranks, explains and never blocks.
- **Synthetic profiles** (no GPU, 6 GB, 8 GB, 12 GB with 16 GB RAM, 24 GB) are test fixtures for QA-43.

### P21.1 catalog format

The catalog is [`backend/src/main/resources/inference/model-catalog.json`](../backend/src/main/resources/inference/model-catalog.json), read by `org.rpgengine.inference.catalog.ModelCatalog`. The format `rpg-engine.model-catalog/1` is closed: an unknown, missing or duplicated field, a wrong type or an out-of-range value rejects the whole file with a rule code and a JSON Pointer.

| Field | Content and rule |
| --- | --- |
| `schema`, `revision`, `reviewed` | Format name, a revision raised with every content change, the date the source facts were checked |
| `entries[]` | In preference order; the advisor's last tie-break. `id` is lower case and unique |
| `kind`, `format` | `text` with `gguf`, or `image` with `safetensors`. No pickle or other executable format is admitted (ADR 0021 decision 9) |
| `source` | `host` (`huggingface` or `civitai`), `page`, `repository`, `revision` (a 40-digit commit, or a CivitAI model-version number) |
| `files[]` | `role` (`weights` exactly once, `vae`, `projector`), plain `name` with the format's extension, `url` on the source's own HTTPS host and pinned to the revision, exact `bytes`, lower-case `sha256`, `verification` (`download` = recomputed from the downloaded bytes, or `source-api` = publisher's digest only) with its date |
| `license` | `id`, `class`, `url`, `basis` (`model-card`, `model-page` or `base-model`), `confirmationRequired` (mandatory for every class except `permissive`) |
| `attribution` | Credit text for the credits registry |
| `requirements` | Text: `kvBytesPerToken`, `kvFixedBytes`, `computeBytes`, `contextMax`, `contextDefault`. Image: `activationBytes` at `resolution`. Both carry `basis` (`estimate` or `measured`) |
| `languages` | ISO 639-1 code to `unnamed` (broad multilingual claim), `named` (the publisher names the language) or `evaluated` (this project's P21.6 evaluation passed). `en` is required |
| `capabilities` | Text: `system-role`, `thinking`, `tool-use-format`, `schema-enforced-output` (through the local server's JSON-Schema grammar; still to be probed in P21.2). Image: `sdxl`, `vae-integrated`, `negative-prompt`, `lora` |
| `slots` | Text slots, or `image` |
| `contentNotes` | `nsfw-capable`, `sign-in-may-be-required`, `monetized-use-forbidden`, `third-party-quantization` |
| `measured` | `null` until a host measurement exists; then `date`, `host`, `peakVramBytes` and, for text, `context` |

License classes: `permissive` (Apache-2.0, MIT); `use-restricted` (open weights with a list of prohibited uses: OpenRAIL++ and FAIPL-1.0-SD); `restricted` (further conditions, such as Pony's ban on inference in monetized applications); `unknown`. `permissive` and `use-restricted` rank equally, as "Apache-2.0, MIT or OpenRAIL-style" above. Only those two classes can supply a default.

How the text estimates are derived from the GGUF headers (f16 cache): bytes per token = global-attention layers × KV heads × (key + value length) × 2. Fixed cache = sliding-window layers × KV heads × (key + value length) × 2 × (window + 512-token batch), or the recurrent state for Qwen3.5. Layers that reuse another layer's cache are not counted. Compute buffers are rough allowances dominated by the 262,144-token (Gemma) and 248,320-token (Qwen) vocabularies at a 512-token batch. Contexts default to 32,768. The image activation figure is a single rough allowance for SDXL at about one megapixel. P21.2 and P21.5 replace every one of these with measurements.

### P21.1 hardware profile

`./start.sh --models profile` writes `.local/hardware.json` (format `rpg-engine.hardware-profile/1`) and prints a two-line summary. `--gpu-check` adds the container check. It uses only Bash, the ADR 0009 utilities, `docker` and three optional probes: `nvidia-smi` (on `PATH`, or WSL's `/usr/lib/wsl/lib/nvidia-smi`), `powershell.exe` (Windows only) and `df`. A missing or failing probe is recorded and never aborts the command.

| Field | Source |
| --- | --- |
| `generatedAt`, `platform` | UTC time; `windows` (Git Bash), `wsl`, `linux`, `macos` or `other` |
| `cpu` | `model name` and the `processor` count in `/proc/cpuinfo` |
| `memory` | `MemTotal` and `MemAvailable` in MiB; `scope` is `vm` under WSL, where the kernel sees only the VM. On Windows, `modules` (capacity, configured speed) and `moduleSlots` come from the CIM classes `Win32_PhysicalMemory` and `Win32_PhysicalMemoryArray`; elsewhere both are `null` |
| `gpuSource`, `gpus[]` | `nvidia-smi --query-gpu=index,name,memory.total,memory.used,memory.free,driver_version,compute_cap --format=csv,noheader,nounits`. Never the Windows adapter field, which reports about 4 GB on the 12 GB card. `[N/A]` becomes `null` |
| `disk` | Free space under `.local` (`df -Pk`) |
| `containerEngine` | `docker info`: OS type, version, operating-system label, memory (the WSL 2 VM's under Docker Desktop) and CPUs |
| `containerGpu` | `not-checked` without `--gpu-check`. With it: the pinned image runs `--list-devices` with `--gpus all`, no network, a read-only root, no capabilities, `no-new-privileges` and user 65534, and is removed afterwards. A missing image is first pulled by digest (about 2.6 GB). `visible` = a CUDA device was listed (with its total and free memory as CUDA reports them inside the container); `not-visible` = the image ran and listed none, or Docker could not attach a GPU; `failed` = the pull or run failed otherwise; `engine-unavailable` = no Linux container engine answered |

The profile records hardware models, sizes and versions only: no host or user name, serial number, GPU UUID, address or absolute path. Six fixtures in `backend/src/test/resources/inference/hardware-profiles/` are generated by the launcher from recorded tool output, and a test keeps them byte-identical: `reference-host` replays the 25 October measurements, with free VRAM taken as total minus used (11,012 MiB), and with the WSL VM memory measured on 28 October; `reference-host-gpu-visible` adds a synthetic container answer (10,776 MiB free); `no-gpu`, `gpu-6gb`, `gpu-8gb` and `gpu-24gb` are synthetic. None of them is evidence about a real machine.

### P21.1 advisor rules

`org.rpgengine.inference.catalog.ModelAdvisor` is pure and deterministic. Defaults: 1,024 MiB VRAM margin, 3,072 MiB memory reserve for the engine, database and operating system, and a minimum text context of 16,384 tokens.

1. **GPU budget.** Free VRAM of the first GPU, taken from the container's CUDA view when `--gpu-check` saw one, otherwise from the driver tool (free, or total minus used), minus the margin. Free VRAM already excludes the desktop and other applications at profiling time. Several GPUs are not scheduled (ADR 0021, "Not decided").
2. **Memory budget.** The container engine's memory, otherwise system memory, minus the reserve.
3. **Text fit.** Files + fixed cache + compute + bytes per token × context. The largest context that fits, in steps of 1,024 tokens and at most `contextMax`, must reach the minimum. The proposed context is the smaller of that and `contextDefault`. The GPU is tried first (`GPU`), then memory (`CPU`, slow), otherwise `TOO_LARGE`.
4. **Image fit.** Files + activations within the GPU budget, otherwise `TOO_LARGE`. No CPU fallback.
5. **Ranking per kind.** Fit (`GPU`, `CPU`, `TOO_LARGE`); a measured profile first; license (`permissive` = `use-restricted`, then `restricted`, then `unknown`); English and Italian coverage (`evaluated` 3, `named` 2, `unnamed` 1, absent 0, summed); for `CPU` fits only, smaller files first, because decoding speed on the CPU is bounded by memory bandwidth divided by model size; then catalog order.
6. **Recommended default.** The first ranked entry that fits, has every digest verified from downloaded bytes and a `permissive` or `use-restricted` license. There may be none.
7. **Notes.** Every assessment explains itself: `CONTAINER_GPU_UNVERIFIED`, `CONTAINER_GPU_NOT_VISIBLE`, `CONTEXT_REDUCED`, `CPU_ONLY_SLOW`, `EXCEEDS_VRAM`, `EXCEEDS_MEMORY`, `ESTIMATE_ONLY`, `HASH_UNVERIFIED`, `LICENSE_CONFIRMATION`, `LICENSE_RESTRICTED`, `ITALIAN_UNCONFIRMED`, `NSFW_CAPABLE`. Host notes: `NO_GPU`, `GPU_TOOL_FAILED`, the container notes and `SINGLE_MEMORY_MODULE` (one module on a multi-slot board).
8. **Presets.** Local-only (the recommended text model in all three text slots, as one resident model, and the recommended image model or none), hybrid (local `light` and `standard`, `deliberate` on the agent runtime or an owner-chosen API) and cloud-first (all text on the runtime). Local-only and hybrid are unavailable without a recommended text model. Every entry is still listed, and the owner may choose any of them.

### P21.2 model fetch

`./start.sh --models fetch [--accept-license ID[,ID...]] ID...` is implemented and tested on fixtures only. **No real model has been downloaded with it.** There is no default model and no "all": each model is named.

| Step | Where it runs | Rule |
| --- | --- | --- |
| Arguments | Host | A malformed ID, an unknown option, no ID, or an `--accept-license` value with a wildcard, an empty element or an ID this command does not fetch exits 2 before any Docker call |
| Show the license | `models-license`: no network, no model directory, read-only mounts | Prints the license ID, class and basis, the URL of its terms, the source page, the attribution, content notes and each file's URL, size and SHA-256. The catalog holds a link and not the license text. An ID outside the catalog exits 2 |
| Confirm | Host | Each model named by `--accept-license` is accepted. Every other model needs the exact answer `yes` on a terminal. Any other answer, end of input, or a missing terminal exits 1 before any download. The question is asked for every license class: `confirmationRequired` stays an advisor note (`LICENSE_CONFIRMATION`) and never skips it |
| Download and verify | `models-fetch`: bridge network, the model directory writable | Files go to `.partial/run-*/NAME.part`, which the model server's scan does not treat as a model. A declared length that differs, a body past the catalog size, a short body or another digest fails the command. The helper repeats the confirmation check and refuses an ID missing from its `--accepted` list |
| Install | `models-fetch` | Only after every file of every requested model has passed, each moves to `MODELS_DIR/NAME` with mode 0644 where the host honors modes. Any failure installs nothing from that command, and a failed move undoes this run's earlier moves |

- **Non-interactive confirmation.** `--accept-license` is how a recorded owner decision is applied without a prompt, for example `./start.sh --models fetch --accept-license gemma-4-12b-it-qat-q4_0 gemma-4-12b-it-qat-q4_0`. The license is still printed. Naming the ID is the owner's acceptance of the license shown for that catalog revision, so it must not be scripted without that decision.
- **Existing files.** A file with the catalog's exact size and digest is reused without a download. Anything else under that name, including a symbolic link, fails the command before any download and stays untouched. Removal is the owner's act until `--models remove` exists.
- **Directory.** `MODELS_DIR`, default `./.local/models`, as for the `models` service. Files sit directly in it under their catalog names, the single-file layout of the llama.cpp router. A new directory gets mode 755, because the server runs as user 65534. An existing directory keeps its mode.
- **Transport.** The helper is `docker/model-fetch/model_fetch.py`, standard library only, in the pinned Python image. Catalog URLs and redirects must be HTTPS. Redirects may change host, because publishers serve files from their storage hosts and the digest decides the file's identity. No token is sent, so a source that asks for a sign-in fails with its HTTP status.
- **Interruption.** On Ctrl+C the launcher stops the named container, and the stop signal makes the helper remove `.partial`. A hard kill can leave `.partial` behind, and the next fetch removes it. That also fails a concurrent fetch on the same directory, which then installs nothing.
- **Tests.** A fixture catalog sits at the catalog's own path in a temporary copy, so the launcher has no setting that names another catalog. URLs are under the reserved `.invalid` domain. The evidence and what is not proven are in the [roadmap](16-development-roadmap.md) P21.2 entry.

## 6. Freedom, probes and hard limits

- **Open by default.** The owner may drop any GGUF or safetensors file into the model directory, name a Hugging Face file with its hash, point to a compatible endpoint, or enter an API key. The engine runs the readiness probe, shows the result, records the hash as "trust on first use" when none is pinned, and labels the model unverified.
- **Readiness probe.** A neutral task set checks the output contract for the slot, English and Italian text, a context-length sample and latency. A failed contract blocks `standard` and `deliberate` for structured tasks, and the owner can still use a prose-only model for narration. Probe results never certify quality.
- **Implemented so far (P21.2-C, 31 October 2026).** `tools/container_packaging/model_probe.py` probes a server's `GET /health` and then eight JSON-Schema probes (narration beat, intent parse, dialogue line and turn summary, each in English and Italian) in `probes/narration-probes.json`, printing a visible `PASS` or `FAIL` per probe. It is proven only against a scripted loopback fixture, which is not a model. No real server or model has been probed, the context-length sample is not yet a probe, and the engine does not run these probes itself (P21.3). The measurement record format `rpg-engine.model-measurement/1` (load time, prefill and decode speed, peak VRAM and RAM, context limit, VRAM released by unload, probe results) is defined and validated, with a sample whose metrics are all null. The column `measured` of the catalog stays `null`: the host measurements of P21.2-D are recorded in section 7 only, and no catalog entry or advisor ranking changed. Run against the five real models on 1 November 2026, the probe set gave 0 passed and 8 failed on every model (`reply is not valid JSON`, exit 1); see section 7 for the cause and what it does not show.
- **Hard limits.** No pickle checkpoints, remote code, custom nodes or extensions in managed backends. Model servers have no network egress. Endpoints must be on the owner's allowlist (HTTPS, or loopback and private addresses after explicit confirmation), and redirects to other hosts are refused. Keys, endpoints and downloads come only from owner actions, never from packs, prompts or model output. No backend is offered tools.
- **Not delegated to the model.** Schema validation, audience isolation, content policy and authority rules stay engine-side, whatever the model's own tuning.

## 7. Local text server profile

- **Image and runtime.** The pinned llama.cpp `server-cuda` image: `server-cuda-b11960` by index digest since P21.1 (section 2). The image itself runs as root and has no `USER`, so Compose sets user 65534. Non-root, read-only root filesystem, dropped capabilities, `no-new-privileges`, a private network and no route to the Internet or PostgreSQL. Weights are on a read-only bind of the model directory.
- **Packaged service (P21.2-A, implemented).** The Compose service `models` carries this image behind the `models` profile, so a plain `up` neither pulls nor starts it; select it with `docker compose --profile models up --detach models`. ## 8. Local image worker profile

- **Worker.** A pinned container with PyTorch for CUDA and diffusers (Apache-2.0), loading single-file SDXL safetensors checkpoints and LoRA files from the read-only model volume. Same hardening as section 7, no network. It follows the pattern of the speech worker in [local speech](30-local-speech-synthesis.md).
- **Packaged service (P21.5-A, implemented; the image has never been built).** The Compose service `image-worker` builds `docker/image-worker` behind the `images` profile, so a plain `up` neither builds nor starts it; select it with `docker compose --profile images up --detach --build image-worker`. It runs as UID/GID 10003, publishes no port and joins only the internal `images` network, which it shares with the engine alone. It mounts `MODELS_DIR` read-only, the same directory as the text server. It requests all GPUs, and without a CUDA device a load answers 503 `gpu-unavailable` rather than running on the CPU. The launcher has no command that selects it, though `--stop` stops it. Engine code can reach it since P21.4-D, only with `engine.inference.image-worker.url` and the admission switch set ([section 10](#p214-d-packaged-image-worker-behind-the-lease-executor)); no Compose file sets that address.
- **Pins.** The base is the Python image that the gateway and the fetch helper already pin. Every package, torch 2.15.0 for CUDA 13.2 and diffusers 0.42.1 among them, is installed by exact version and SHA-256 from `requirements.lock` with `--no-deps`, then `pip check` runs. PyYAML has no wheel for Python 3.15, so it is built in pure Python from its hash-pinned source with a hash-pinned setuptools.
- **Offline loading.** A single-file checkpoint holds weights only, and the loader would otherwise fetch its configuration online, even under `local_files_only` when none is found locally. So 14 configuration and tokenizer files of the SDXL base 1.0 revision that the catalog pins are baked into the image by checksum, and every load names that directory. Checkpoints sit at the top of the model directory, and a LoRA in `loras/` below it. Pony's checkpoint needs its catalog VAE and fails with `vae-missing` without it.
- **Routes.** `GET /healthz` (process only), `GET /v1/models` (`recommended`, `alternatives`, installed files, what is loaded, the policy), `POST /v1/load` (`checkpoint` is a catalog ID or file name; omitted means WAI-illustrious v17.0), `POST /v1/unload`, `POST /v1/generate` (`prompt`, and optionally `negativePrompt`, `width`, `height`, `steps`, `guidanceScale`, `seed`, `loras`) and `POST /v1/cancel`. The answer holds the PNG in base64, the seed, the settings used and a provenance record. One job runs at a time, and another gets 409 `busy`, because the queue belongs to the coordinator (section 10). A file reaches a loader only as one path segment, inside the model directory, with a safetensors header whose tensors end exactly at the file's size. A checkpoint must also hold SDXL's second text encoder.
- **Generation.** Euler ancestral sampling, by default 24 steps, CFG 6 and 832×1216. CLIP takes 77 tokens, that is 75 of content. Tag-style prompts exceed that, so the worker splits the tokens itself (no third-party helper; [ADR 0021](adr/0021-inference-backends-and-model-selection.md)). A chunk ends after the last comma of its final 20 tokens, or at 75 without one, and no token is lost or moved. Each chunk is encoded alone by both encoders and joined along the sequence, the shorter of prompt and negative prompt gets empty chunks, and the pooled vector comes from the first chunk. More than 8 chunks are refused with `prompt-too-long`, never cut. Weight syntax such as `(tag:1.2)` is not interpreted. Cancellation, validation and provenance are in the next three bullets; the asset pipeline hashes the output again on its side.
- **Cancellation (P21.5-B.1).** `POST /v1/cancel` takes no fields and is served without the job slot, so it works while a generate job holds it. It answers 200 `{"cancelling": true}`, or 409 `no-job` when no generate job runs, which includes a load or unload: those cannot be cancelled. The backend checks the request before the first step and in the pipeline's step-end callback, which raises out of the pipeline, so later steps and the final decode never run. The cancelled request itself answers 409 `cancelled` with no image. A request that was already past its last step is cancelled too: the worker drops that finished image, so a cancel that was acknowledged never yields a result. The slot is freed, the LoRAs of the job are removed, the backend's cached GPU memory is returned (`trim`), and the checkpoint stays resident. *Limits:* a cancel takes effect at the next boundary, so a step in progress, the text encoding and the decode are not interrupted. A client that disconnects does not cancel its job, and the engine must call the route. A cancel carries no job ID, because one job runs at a time; a cancel that arrives after its job ended answers `no-job`, and one that arrives while the next job is already running would stop that job, which is for the coordinator to prevent.
- **Output validation (P21.5-B.1).** An image is returned only after `validate_png` accepts it, else 500 `invalid-output` and the image is dropped. It requires at most 32 MiB, the PNG signature, IHDR first with dimensions that equal the request and lie within 512 to 1536, a legal color type and depth without interlacing, a correct length and CRC for every chunk, IEND last with nothing after it, and an IDAT stream that inflates to exactly the size the header implies (read with a bound, so a small file cannot expand without limit) with a legal filter byte on every row. *Limits:* this proves a well-formed file of the requested size, not that the picture is good, blank or safe; content review is engine-side (section 6).
- **Provenance (P21.5-B.1).** Each result carries a `provenance` object: the worker version, the SHA-256 of the worker's source and of the installed `requirements.lock` (null outside the image), the versions of torch, diffusers, transformers, peft, safetensors and pillow, the checkpoint (name, catalog ID, SHA-256), the VAE and each LoRA (name, SHA-256, weight), seed, steps, guidance, sampler `euler-ancestral`, size, the policy in force, the SHA-256 of the prompt, the negative prompt and both composed texts, and the SHA-256 and byte count of the output. It never holds prompt text. *Limits:* the checkpoint is hashed when it is loaded, so a first load reads the whole file once; a hash shows which file bytes were read then, not that the loaded weights were not changed on disk afterwards; LoRA hashes are cached by size and modification time. A hash of a short or guessable prompt can be matched by guessing, so the record is not secret. The worker returns the record and stores nothing: the asset pipeline owns what is persisted.
- **Content policy.** The recommended checkpoint can render explicit content, so the safe defaults below apply to every job. They come first, so they always fall in the first chunk. A caller's negative prompt adds to them. A request has no field that changes them and any unknown field is refused. Under `safe`, a positive tag that the defaults forbid, in any spelling of case, underscores or weight syntax, is refused with `prompt-conflicts-with-safe-defaults`. This compares whole tags: it is not a content filter, and policy stays engine-side (section 6). For private use the owner sets `IMAGE_CONTENT_POLICY=owner-private`, which keeps only the quality tags; any other value stops startup, and every answer reports the policy in force. The repository ships no generated art without review ([publication](18-github-publication.md)).

  | --- | --- | --- |
  | WAI-illustrious v17.0 (recommended) | `general`, `masterpiece`, `best quality`, `amazing quality` | `nsfw`, `explicit`, `sensitive`, `nude`, `nudity`, `sexual content`, and the quality terms `bad quality`, `worst quality`, `worst detail`, `sketch` |
  | Pony Diffusion V6 XL | `rating_safe`, `score_9`, `score_8_up`, `score_7_up` | `rating_explicit`, `rating_questionable`, the same explicit terms, and `score_4`, `score_5`, `score_6` |

  | A file the owner added | `general` | the same explicit terms |
- **Not proven (P21.5-A, P21.5-B.1; the `a1111-http` adapter is listed under its own bullet).** The image was not built in the session that wrote it, so the lock, the PyYAML build, the configuration URLs and `test_image_worker_container.py` have never run. No checkpoint or LoRA has been loaded and no image generated, on any device, so the tag lists, VRAM use, speed and the effect of unloading are unmeasured. The cancellation, validation and provenance tests run on recording stand-ins without torch, a GPU or weights: that diffusers accepts `callback_on_step_end` with an empty tensor list and propagates the exception cleanly, that `trim` really returns VRAM, and that a real pipeline writes a PNG that `validate_png` accepts have not been observed. Evidence is in the [roadmap](16-development-roadmap.md) P21.5 entry.
- **Attribution and licenses.** Source, hash, license and notice are stored and shown. The engine never redistributes weights. CivitAI may require the owner's sign-in or an API token for the WAI-illustrious download. On 28 October 2026 both CivitAI checkpoints and the VAE downloaded anonymously (section 2), which can change. The fetch command (P21.2) sends no token today, so such a source fails with its HTTP status. Taking a token from the owner's environment for one command, without storing it, is still planned.
- **Bring your own server.** The `a1111-http` adapter drives an owner-run Forge or A1111 server over its documented HTTP API through the gateway. Its VRAM use is not coordinated, so the engine only serializes its own requests and reports contention. Forge itself is not packaged.
- **Image-generation port (P21.5-B.2, implemented).** `ImageGenerationPort` (`backend()` and `submit(ImageRequest)`), `ImageHandle` (`result()` and `cancel()`), `ImageRequest`, `ImageResult` and `ImageProvenance` are public types of `org.rpgengine.inference`, covered by `InferenceBoundaryTest`. P17.6 builds the runtime asset jobs on them ([presentation assets](23-presentation-assets.md)); nothing in the running application constructs an adapter yet, and the port holds no job queue of the game and no authority rule.
  - *Request.* Prompt and negative prompt (each at most 8192 characters, the prompt not blank), an optional checkpoint name, width and height (512 to 1536 in steps of 8), steps (1 to 60), guidance (1 to 12), an explicit seed (0 to 2³²−1) and an optional sampler. These are the worker's own bounds, so one request is valid for every adapter. The record has no other field, so no game state can be passed, and a test pins that list. A violation throws `IllegalArgumentException` naming the field, never the value.
  - *Result.* `submit` never blocks on the backend and never throws for a backend condition. The result stage completes once, never exceptionally, as `COMPLETED` (validated PNG plus provenance), `CANCELLED` (no image) or `FAILED` (a fixed code, no server text or address). `cancel()` returns false when the job had already finished. A queued job is cancelled at once; a running job is interrupted on the backend, and an acknowledged cancel never yields an image, even if the backend still returned one.
  - *Provenance.* `ImageProvenance` holds the backend name, the checkpoint name requested, the checkpoint hash the server reported (null if none), the sampler, seed, steps, guidance and size sent, the SHA-256 of the prompt, of the negative prompt and of the validated PNG, and the PNG's byte count. It holds no prompt text.
  - *Implementations.* The `a1111-http` adapter implements the port, and since P21.4-D so does `WorkerImageAdapter` (backend `local-image`) over the packaged worker, unchanged ([section 10](#p214-d-packaged-image-worker-behind-the-lease-executor)).
- **The `a1111-http` adapter (P21.5-B.2, implemented; only scripted fixtures have answered it).**
  - *Gateway profile.* A gateway destination with `"protocol": "a1111-http"` can reach exactly `POST /sdapi/v1/txt2img`, `POST /sdapi/v1/interrupt` and `GET /sdapi/v1/progress`, each only with its own method (405 `method-not-allowed` otherwise). Every other route of the server, such as its options, checkpoint reload and shutdown routes, and any sub-path, is refused with 403 `path-not-allowed` before contact. The owner may omit `path_prefixes` or narrow them to a subset of these routes, never widen them. The profile's defaults are 1 MiB per request, 32 MiB per response (a base64 PNG in one JSON document), 300 seconds and no redirect; the owner can change those fields within the gateway's ceilings. All other gateway rules apply unchanged: the allowlist chooses the host, cookies cross in neither direction, a redirect cannot leave the origin or the listed routes, an upstream error body is discarded, and a call is bounded in time. An owner-run server started with basic authentication uses the gateway key file with the `Authorization` header and the `Basic ` prefix; over plain HTTP that needs `plaintext_key`, the owner's explicit choice for a LAN server.
  - *Serialization and contention.* The adapter runs its own jobs one at a time on one thread behind a bounded queue (8 by default); a full queue fails the submission with `image-queue-full`. Before each job it reads `GET /sdapi/v1/progress?skip_current_image=true`: if the server reports `state.job_count` above zero, the job fails with `image-server-busy` and nothing is sent. The engine does not wait behind, and never interrupts, work it did not start. Contention is therefore reported, not resolved, and the VRAM use of the owner's server remains uncoordinated.
  - *Cancellation.* `POST /sdapi/v1/interrupt` stops whatever the server is generating, so the adapter sends it only while its own txt2img call is in flight. A residual race remains: if the server finishes our job and another client starts one within the latency of the interrupt call, that job is interrupted. If the interrupt call itself fails, the server finishes its render and the result is still `CANCELLED`, delivered when the generation call returns or times out.
  - *Request.* One image per call (`batch_size` and `n_iter` 1), `save_images` false, `send_images` true. A checkpoint name is sent as `override_settings.sd_model_checkpoint` with `override_settings_restore_afterwards`; without a name the server's current checkpoint is used.
  - *Output validation.* The answer must be a JSON object with exactly one string in `images`. That string must be strict base64 (`image-bad-encoding`), decode to at most 24 MiB, and be a well-formed PNG (`image-bad-png`) of exactly the requested size (`image-wrong-size`): signature, `IHDR` first with a legal color type and depth and no interlacing, every chunk's CRC, consecutive `IDAT` chunks whose stream inflates to exactly the size the header implies with legal filter bytes (read with a bound), and `IEND` last. The stored PNG keeps only `IHDR`, `PLTE`, `tRNS`, `IDAT` and `IEND`: servers write the prompt and their settings into text chunks, and those would otherwise travel with the image. A structural check proves a well-formed file of the requested size, not that the picture is good or safe.
  - *Failure codes.* `image-queue-full`, `image-server-busy`, `image-timeout`, `image-unreachable`, `image-status`, `image-destination-not-allowed` (the gateway refused the destination, path or method), `image-response-too-large` (the gateway's or the adapter's own 32 MiB bound), `image-malformed`, `image-bad-encoding`, `image-bad-png`, `image-wrong-size`, `image-interrupted` and `image-shutdown`. The adapter follows no redirect, keeps no cookie and never forwards server text. Its own call bound defaults to 330 seconds, above the profile's 300, so that the gateway's fixed refusal arrives first.
  - *Not proven.* No real Forge or A1111 server has answered: the route shapes, the `state.job_count` reading of an idle and a busy server, that an interrupted txt2img returns promptly, the `info` document's `sd_model_hash`, and the PNG a real server writes are read from its documentation. The adapter has no Spring configuration, so no setting selects it, and no launcher command writes the gateway destination. The P17.6 runtime jobs are not built.

## 9. Gateway: hosted APIs and custom endpoints

- A single `gateway` container joins an egress network and a private network shared only with the engine. Keys are runtime-only secret files, set with a launcher command that never echoes them. They never enter the database, the frontend, logs or images.
- It speaks `openai-compatible`, `anthropic-api`, `openai-images` and `a1111-http`. It enforces the destination allowlist, request and response bounds, time budgets, no cookies and no cross-host redirects. It sets the model and parameters on every call and applies the retry and quota rules of [asynchronous planning](28-asynchronous-narrative-planning.md).
- **Budgets.** A metered slot has a daily and a monthly cap kept by the gateway. Reaching a cap stops that slot with a clear status. It never moves the work to another class.
- **Status.** The container, the allowlist, the runtime-only keys and the request, response, time, cookie and redirect rules exist since P21.3-C.1 ([section 12](#p213-c1-gateway-container)). Budgets exist since P21.3-C.2, counted in relayed calls ([section 12](#p213-c2-gateway-budgets)). The `a1111-http` protocol profile (three exact routes with their methods, image-sized bounds, no redirect by default) exists since P21.5-B.2 ([section 8](#8-local-image-worker-profile)). The launcher's key command and the remaining protocol behavior (the model and parameters on every call, retry and quota rules, and any count of tokens or images) are planned.
- **Starting points** for hosted text, to be validated by the probe: Anthropic Haiku 5.5, Sonnet 5.5 and Opus 5.5 for light, standard and deliberate; OpenAI models as the owner configures. Identifiers are owner settings, not product constants.

## 10. Shared admission and speed

On the 12 GB host one heavy model is GPU-resident at a time. The coordinator of [local speech §8](30-local-speech-synthesis.md) is extended to text.

- **Priorities.** Interactive text (intent, narration, tactics) first; image for the scene being read; speech; background summaries and planning; pre-generation last.
- **Text queue.** Text tasks already pass through the P08.6 fair scheduler, which owns their priority classes, the single text turn permit, quotas and restart reconciliation ([docs/06 section 12](06-codex-integration.md#p086-durable-fair-scheduling)). The coordinator sits behind that permit for text (a text task holds a GPU lease only while it holds the scheduler's permit) and adds image and speech leases beside it; it never creates a second text queue.
- **Lease.** An image or speech job asks for a lease. The coordinator saves the narration slot's prompt cache, unloads the text model with `POST /models/unload`, confirms the VRAM was freed, runs the batch, reloads with `POST /models/load` and restores the cache. Image batches are grouped to pay the swap once, and a lease has a time cap.
- **Interruption.** A diffusion job checks for interactive demand between steps and yields. No lease starts while a text request is queued or expected within the reading window.
- **Profiles.** Admission needs a measured VRAM and load-time profile for the exact model and precision. An unprofiled model is admitted only alone, with extra headroom.
- **Unowned contention.** The owner's games or other applications reduce free VRAM. The coordinator rechecks, delays or falls back to text-only play or catalog art. It never terminates another process.
- **Memory.** Keep models fully on the GPU; CPU offload is slow here. The launcher advises on WSL memory and never changes WSL, Docker or driver settings.

### P21.4-A admission coordinator core

Implemented in `org.rpgengine.inference.admission` and migration `V29__resource_leases.sql` (31 October 2026, task still open). It is the policy and the durable record only: it loads, unloads and measures nothing, and it reserves capacity on paper. Nothing called it when this story closed; [P21.4-C.1.2.1](#p214-c121-opt-in-construction-of-the-lease-executor) now builds it behind the opt-in switch and [P21.4-C.1.2.2.1](#p214-c1221-link-from-the-schedulers-text-permit-to-the-lease-executor) adds the driver that submits requests to it.

- **Budget.** `AdmissionSettings` names the GPU and RAM bytes the engine allows itself in total (the caller sets it below the real total), a lease lifetime, an aging step and a batch limit per modality (text, image, speech, at most 64). A request whose model alone exceeds the budget is refused at submission.
- **Priority.** The class is the scheduler's `WorkClass`. Interactive requests go first; a background request gains one class per aging step, never above `CONTINUITY` and never over interactive work. The modality order sketched above (image for the scene being read before speech) is not encoded: the caller picks the class, and equal classes rotate.
- **Fairness.** Among requests of equal rank the modality served least recently in that tier goes first, then the owner (normally the campaign) served least recently, then the oldest. A flood of text cannot hold back speech or images, nor one campaign another.
- **Leases and batching.** One lease holds one resident model and its demand, counted once however many compatible requests (same modality and model) share it. A request joins a resident lease with room at no extra capacity; a request that creates a lease takes the other waiting requests for the same model with it, up to the batch limit. Joining does not extend a lease: the holder renews it, and a lease expires one lifetime after its last renewal. The last member to finish releases it.
- **No overtaking.** When the first request in order cannot be admitted, nothing behind it is, not even by joining a lease, so leases drain and a large request is not starved by small ones.
- **Taking back.** `preemptionVictims` names background-only leases, newest first, when the first request in order is interactive and cannot run; it names nothing if revoking all of them would still not make room. The caller interrupts and unloads, then revokes; capacity counts as free for the next admission only after the revoke.
- **Durable record.** V29 `resource_lease` stores a lease's id, owning process, modality, model, byte counts, member count, status and times, and no prompt, output, key or endpoint. A grant is written before it is returned, and a refused write puts the requests back in line. After a restart `recover` moves every open lease of an earlier process to `RECONCILING` under the new process, and its capacity stays reserved until a caller confirms the model is gone (`confirmUnloaded`). Only the owning process may renew or settle a row. The table's trigger repeats the lifecycle, so a defect fails loudly.

Limits: by default a lease that expires frees its capacity in the accounting at once, whether or not the model is still resident; the rule P21.4-B adds holds it instead. The capacity total is enforced in the process, not by the database, so two engines sharing one database are not supported. Batched requests share one demand: the memory a batch member adds (for example its cache) is not modelled. Not built by this story: everything P21.4-B lists below. No out-of-memory proof exists.

### P21.4-B lease executor over the model server

Implemented in `LeaseExecutor` and its settings in `org.rpgengine.inference.admission`, the neutral `ModelServerControl` and `ModelControlException`, and `LocalModelControl` in `org.rpgengine.inference.local` (31 October 2026, task still open). No migration was needed: V29 already allows a lease to move from `ACTIVE` to `RECONCILING`. Tested against a scripted HTTP server, a scripted worker and a scripted memory reading, which are fixtures and show nothing about a real server, worker or card.

- **Server routes.** `POST /models/load` and `POST /models/unload` with `{"model"}`, `GET /models` for each model's status, and `POST /slots/N?action=save|restore` with `{"model","filename"}`, following the llama.cpp server documentation (section 2). A load or unload answer only means the request was accepted, so the executor confirms the result in the model list. Each call has one deadline (2 minutes), follows no redirect and reads at most 1 MiB. Failures are fixed codes: `control-timeout`, `control-unreachable`, `control-status`, `control-malformed`, `control-too-large`, `control-interrupted`, `load-failed` and `load-unconfirmed`. Server text and the address are dropped.
- **Which models are resident.** Every model in memory is covered by a live lease or a hold, or it is an unleased text model that stays warm for the next turn. A warm model counts for nothing in the coordinator's accounting, so admission ignores it, and the executor counts it itself before every load. It is evicted before a requested model that does not fit beside it loads, and a model that fits beside it causes no swap. A swapped-out text model comes back on its own only if it fits on paper beside every lease, hold and warm model, GPU and RAM alike and whatever the memory reading says, with the model evicted last going first. Such a reload never evicts, so two text models that do not fit together do not swap on every pass: the model left out waits for room or for its own text request.
- **Batch order.** `runBatch` checks the start conditions, checks free memory, saves the slot's cache, unloads the text model, confirms it left the model list and that the free reading now covers the demand plus headroom, loads the batch's model, runs its steps, unloads that model, ends the lease, reloads the text model and restores the cache. The cache file name is a hash, so it never repeats the model name.
- **Failures.** A failed save costs the cache only, and the text model comes back cold. A failed or unconfirmed text unload loads nothing and the text model stays usable. A failed or unconfirmed unload of the batch's model keeps its lease `RECONCILING` with its capacity held, and `pass` retries after `recheck`. A failed reload does not fail the batch that already ran: `pass` retries it after `recheck`, and a text request that needs the model tries itself. A failed restore leaves the model loaded and cold, because the adapter resends its conversation anyway. A batch model that will not load is confirmed gone before its lease ends.
- **Expiry.** A coordinator created with `Expiry.HOLDS_UNTIL_UNLOADED` moves an expired lease to `RECONCILING` and holds its capacity until its unload is confirmed, and the executor refuses any other coordinator. An expired running job stops at its next step boundary. A step that never returns keeps the capacity held, which is the safe side.
- **Restart.** `start` takes over open leases and unloads their models, keeping each hold until that is confirmed. A text model found resident with no lease counts as warm with the whole budget as its unknown size, so any batch evicts it, and only a text request brings it back. Until the server has answered once, no batch starts.
- **Interruption.** Between two steps a job renews its lease when half its lifetime has passed and stops when `preemptionVictims` names its lease: a background-only lease, when an interactive request cannot otherwise fit. The model unloads first, then the lease is `REVOKED`, then the text model reloads. Interactive demand that fits beside the job does not interrupt it. A lease of interactive class is not named, so an interactive text request waits for it to finish or reach its time cap (`timeCap`). A background text holder polls `shouldYield`; `yieldText` frees its capacity and leaves its model warm.
- **Start conditions.** No batch starts while an interactive text request is queued or the injected `expectedDemand` says one is expected, which is the place for the reading window. Those requests are put back and ask again after `recheck`, keeping their original age, with no limit on deferrals.
- **Cancelling.** `LeaseExecutor.cancel` withdraws a request that waits in the queue or was put back to ask again, so it is not granted again and leaves the `requests_delayed` gauge. `AdmissionCoordinator.cancel` cannot see a request put back by the executor, so callers use the executor's. A request that holds a lease is not withdrawn, because its model may be in use, and `cancel` answers false: its holder ends it, and it is not put back if that lease gives way.
- **Unowned contention.** A model loads only when the injected `GpuMemoryReading` covers its demand plus `headroomBytes`, counting what an eviction would free. A low reading changes nothing on the card: the requests ask again after `recheck` and, past `patience` of contention, end `FELL_BACK` so the caller uses text-only play or catalog art. A running job yields when the reading falls under `runningFloorBytes`. `HostGpuMemoryReading` (P21.4-C.1.1) is the real source: it runs `nvidia-smi --query-gpu=memory.free --format=csv,noheader,nounits` through an injectable command runner with a 5 second default timeout, converts the MiB of the first listed GPU to bytes, and answers unknown (empty) when the tool is missing, exits non-zero, times out or prints anything other than one non-negative whole number per line. It is built by the opt-in wiring of P21.4-C.1.2.1 and driven behind the same switch since P21.4-C.1.2.2.1, and it has never run against a real card. An unknown reading refuses a batch but not a text load, because text keeps the game playable when the reading source breaks. `ModelServerControl` offers no way to stop a process.
- **Metrics.** `LeaseExecutor.metrics()` returns an in-process map of fixed names and numbers only, for leases, waits, swaps, slot actions, interruptions, deferrals and contention, so it cannot hold a key, endpoint, model name, prompt or output. The actuator stays limited to health. The executor writes no log lines.
- **Metrics route (P21.4-C.1.3.1).** With `engine.inference.admission.enabled` on, `GET /api/v1/models/admission-metrics` returns that map as a JSON object, sorted by name. It is owner-only: `LocalHttpAdmission` admits the path as it does the other `/api/v1/models/` routes, and `AdmissionMetricsController` also answers 403 `LOCAL_ADMISSION_DENIED` without the owner attribute. With the switch off the controller bean does not exist and the path has no mapping. The route is GET only and adds nothing to the map, so it carries no key, endpoint, model name or task content. `metrics()` is synchronized, so the read waits while a swap holds the executor's monitor and is not lock-free. Tested with the Spring wiring and a stand-in lease store and control, calling the controller directly; no real HTTP request, session or CSRF flow reached the route.
- **Contention harness (P21.4-C.1.3.2).** [`tools/gpu_contention/contention.py`](../tools/gpu_contention/README.md) is the repeatable way to observe the coordinator under load. One command drives text, image and speech requests against the owner's endpoints beside an owner-supplied competitor program that holds GPU memory outside the engine, samples `nvidia-smi` for the peak, scans server, engine and container logs for out-of-memory lines (counts and line numbers only, never the lines), reads the metrics route above with the owner's session value from a private file, and writes everything to a new JSON file. What it could not observe is written as `unavailable` with a fixed reason: no image or speech endpoint, no route, no `nvidia-smi`, no log. It only records and never loads, unloads or stops a model. Its no-GPU self-test runs against stand-in servers and is run by CI; it is not a step of `verify.sh`. No run against a real server, card or the reference host has been made, so the harness proves no out-of-memory absence.

Limits and what is not proven: no real server, model, worker or card has been used, so whether the documented routes behave as scripted is open, including the router forwarding slot actions by the `model` field and how fast unloading frees memory. The packaged service passes neither `--slot-save-path`, so slots are expected to refuse and every swap to come back cold, nor a switch that turns off automatic loading, so a chat request outside a lease could load a model beside a batch. Not built when this story closed (the construction and the scheduler link since landed, see P21.4-C.1.2.1 and P21.4-C.1.2.2.1 below): Spring wiring and settings, the wiring of `HostGpuMemoryReading` (the reading itself exists since P21.4-C.1.1), the image and speech workers, the link to the scheduler's text permit and to the adapters, measured profiles and the headroom they should set, and the rule that an unprofiled model runs alone. Server calls run under the executor's monitor, so a slow swap also delays `pass` and `metrics`. Each delayed retry writes one more `resource_lease` row, bounded by `patience` for contention but not for deferrals, which end only when the demand passes or the request is cancelled. No out-of-memory proof exists.

### P21.4-C.1.2.1 opt-in construction of the lease executor

Implemented in `AdmissionConfiguration`, `AdmissionOptions` and `AdmissionControls` in `org.rpgengine.inference.admission`, and `LocalControlConfiguration` in `org.rpgengine.inference.local` (1 November 2026, task open). These classes only construct; what runs the executor is P21.4-C.1.2.2.1 below. Tested with `ApplicationContextRunner`, a stand-in lease store and a mocked control, without a GPU, a database or a model server.

- **Switch.** `engine.inference.admission.enabled` (default `false`). Missing, blank or `false` is off: no coordinator, executor, control map, reading or options bean exists and nothing reads the other settings. Any value that is not `true` or `false` stops startup with `engine.inference.admission.enabled must be true or false`. The `JdbcLeaseStore` component still exists in every application, as before; it touches the database only when a coordinator calls it.
- **Owner settings** (`engine.inference.admission.*`): `gpu-budget-mib` is required with the switch on (1 to 1,048,576); `ram-budget-mib` (0 to 1,048,576, default 1,048,576, which means RAM is not budgeted until the owner sets it); `headroom-mib` (0 to 65,536, default 1,024, matching the 1 GiB safety margin of section 3); `patience` (above 0, at most 1 hour, default 2 minutes). The budget is what the engine allows itself, set below the real total. Invalid values stop startup with a message that names the setting and does not echo the value.
- **Fixed placeholders, not measured:** lease lifetime 5 minutes, aging step 1 minute, batch limits text 1, image 4, speech 4, slot 0, running floor off, 240 status checks 1 second apart, recheck 5 seconds, time cap 10 minutes. No expected-demand source exists, so the executor is told that no text request is expected soon. The status checks and the lifetime were 30 checks and 2 minutes until P21.4-C.1.2.2.1: the slowest load recorded in section 7 took 164 s, so 30 checks would have failed most loads, and a lease cannot be renewed during a load.
- **What is built.** `AdmissionCoordinator` over the existing `LeaseStore` bean (the PostgreSQL store in the application) with the system UTC clock and `Expiry.HOLDS_UNTIL_UNLOADED`; `AdmissionControls`, a wrapper around the modality map, holding only `TEXT`, the `LocalModelControl` of the local server; `HostGpuMemoryReading`; and `LeaseExecutor` with a sleeping pause. `LocalModelControl` stays package-private: `LocalControlConfiguration` exposes it as the neutral `ModelServerControl` bean only when `engine.inference.local.url` and the switch are both set, because the boundary test keeps the local package from importing `admission`.
- **Failure at startup.** The switch on without a local URL (no control bean) stops startup with `engine.inference.admission.enabled needs exactly one model server control, which engine.inference.local.url provides`; without `gpu-budget-mib` it stops with a message naming that setting.

Not proven: the wiring was never run against a real database, `nvidia-smi`, GPU or model server, so a start with the switch on in the packaged stack is untested. The budget default for RAM is a placeholder. Any image or speech control remains to build.

### P21.4-C.1.2.2.1 link from the scheduler's text permit to the lease executor

Implemented in `TextResidency` (`org.rpgengine.inference.scheduling`), `TextResidencyDriver` and `TextResidencyConfiguration` (`org.rpgengine.inference.admission`) and `InferenceScheduler` (1 November 2026, task open). Tested with a recording `TextResidency`, a scripted port and an in-memory ledger for the scheduler, and with the real executor and coordinator over a scripted server, memory reading and lease store for the driver. No GPU, model server or real database took part.

- **Switch off, or no bean.** `InferenceScheduler` takes an optional `TextResidency`. No such bean exists unless `engine.inference.admission.enabled` is `true`. Without one, a dispatched task is forwarded at once, as before.
- **Dependency direction.** The scheduler knows only the neutral `TextResidency`, in its own package. The admission package implements it, and already depended on the scheduling package for `WorkClass`.
- **Which tasks.** The driver resolves the task's slot as the local adapter does. A slot on another backend, or one the adapter would refuse, needs no residency: its claim is ready at once and the adapter's own result stands. Any other task becomes one text `AdmissionRequest`, with the task's identity and class, its campaign as owner, the resolved model and the configured demand.
- **Text demand.** `engine.inference.admission.text-gpu-demand-mib` (1 to the GPU budget, default the whole GPU budget) and `text-ram-demand-mib` (0 to the RAM budget, default the whole RAM budget) say what any text model is taken to need. It is one figure for every model, because the catalog holds no measured size. The whole-budget default is the safe side: too large a figure costs waiting or a fallback, and too small a one could overcommit the card.
- **Order.** The ledger row moves to `DISPATCHED`, the permit is taken and residency is claimed. On ready the task is forwarded with what remains of its budget. On settlement the claim is released: `finishText` normally, `yieldText` for a turn that ended preempted. The release happens once when the port's result arrives, whatever becomes of the ledger write. An `UNRESOLVED` result keeps the claim until the port confirms that nothing runs, because the model may still be in use.
- **Ending a wait.** A task waiting for its model holds the permit, and it can still be cancelled (`cancelled`), preempted (`preempted`), timed out (`queue-timeout`, the same budget rule as a queued task) or ended by shutdown (`shutdown`). Each takes effect at once, without a turn or a charge, and withdraws the request from the executor.
- **Refusals.** A claim that cannot be served ends the task `UNAVAILABLE`, without a turn or a charge: `residency-contention` (patience used up), `residency-load-failed`, `residency-lost` (the admission lapsed before the turn) or `residency-unavailable` (driver stopped, or the request refused). A request the executor put back (`DELAYED`, `SWAP_FAILED`) keeps waiting.
- **During a turn.** The driver renews the lease when the turn starts and at half its lifetime, because a lapsed lease would have its model unloaded under the turn. When a renewal fails, the lease lapses or the coordinator names the lease, the scheduler interrupts the turn and it ends `CANCELLED` with `preempted`.
- **Threads.** The driver alone calls `LeaseExecutor.start` (retried by the next tick if it fails) and `pass` (once a second, a placeholder, and when a claim arrives). Every executor call runs on its own `inference-residency` thread. Claims and releases only enqueue work, so the scheduler's drain loop never waits for a server. The driver starts before the scheduler and stops after it, letting queued releases run for up to 15 seconds. A lease left open then is held by the next process until its model is confirmed gone.

Limits and what is not proven:

- No real server, model, GPU, `nvidia-smi` or PostgreSQL lease store was used with the switch on, and the packaged stack was not started with it. No out-of-memory proof exists.
- The default settings may never admit a cold load on the reference host. The memory check needs the free reading to cover the demand plus `headroom-mib`. By the section 7 numbers for `gemma-4-12b-it-qat-q4_0`, 12,282 MiB minus the 1,313 MiB in use before its load leaves 10,969 MiB free, and the load adds 10,621 MiB, so with its true size only 348 MiB of headroom would pass, against the default 1,024. This is arithmetic on recorded numbers, not a run, and no working combination of settings has been chosen or tried.
- A cold load spends the task's own budget. That load took 107.53 s in section 7, so a task with a shorter budget ends `queue-timeout`. The load still finishes on the worker, so the next task finds the model warm.
- The adapter resolves the slot again when it dispatches, so a slot changed between the claim and the turn runs on a model with no lease. The packaged service also keeps automatic loading on, so a chat request could load a model outside a lease.
- A worker busy with a long load delays renewals and passes, which is harmless with the single permit and would need another look with more permits. A lease that outlasts its lifetime during a load ends in `residency-lost` and its model is unloaded.
- Not built: a source of expected text demand (the executor is still told that none is expected), image and speech controls, speech jobs, per-model sizes, and metrics exposure beyond the in-process map. Image jobs came with P21.4-C.1.2.2.2 below.

### P21.4-C.1.2.2.2 image requests through the lease executor

Implemented in `ImageAdmission`, `LeasedImageAdmission`, `ImageSteppedJob` and `AdmittedImage` in `org.rpgengine.inference.admission`, with small changes to `TextResidencyDriver` and `SteppedJob` (1 November 2026, task open). Tested with a recording `ImageGenerationPort`, scripted workers, a scripted memory reading and an in-memory lease store, with the real driver, executor and coordinator. No GPU, adapter, image server, model server or real database took part.

- **Switch off.** No `ImageAdmission` bean exists. A caller takes `provider.getIfAvailable(ImageAdmission::direct)`, whose `submit` calls the adapter at once, returns the adapter's own handle and ignores the ticket.
- **Switch on.** `submit(adapter, request, ticket)` queues one `IMAGE` `AdmissionRequest` with the ticket's class and owner. The ticket also holds `maxWait`, because a port request carries no game data and the caller alone knows how long its image is still useful. `submit` waits for neither a model server nor the backend. It can wait briefly for the coordinator, which is never held across a model server call.
- **Who takes the grant.** `TextResidencyDriver` stays the only caller of `LeaseExecutor.pass`, because a grant is handed out once. It passes image grants to `LeasedImageAdmission`, which runs each created lease's `LeaseExecutor.runBatch` on its own `inference-image` thread and adds a request that joins the lease to the running batch. The driver's worker therefore keeps passing and renewing text while an image runs. A grant whose requests were all cancelled meanwhile releases its lease without loading anything.
- **Steps.** `ImageSteppedJob` runs a batch's images one after another. The image port has no per-step API, so a step is one bounded wait on the current handle (1 second, a placeholder), not one diffusion step. Between two steps the executor checks the same conditions as for any job. The port's `cancel` is what reaches the backend, and when it takes effect is the backend's own: the worker's next diffusion step boundary (section 8), or the `a1111-http` interrupt call.
- **Cancelling.** A cancel before the job reaches its adapter ends it `CANCELLED` at once and withdraws the request through `LeaseExecutor.cancel`, so no delay stays behind. A cancel of a running job calls the handle's `cancel` once, at the next step. An acknowledged cancel never yields an image or an error, as in the port's contract.
- **Stopping a running job.** The new `SteppedJob.abandoned` runs once when the executor stops a job or a step throws, on the job's thread and before the model is unloaded, so the backend is not left working on a model that is leaving. The image job calls `cancel` once and waits for the answer for at most 10 seconds (a placeholder), and the model is unloaded after that in any case. An interrupt does not shorten that wait: `LeaseExecutor.runBatch` runs `abandoned` and the unload with the thread's interrupt flag down and sets it again afterwards, because with the flag set each wait and server call there would fail at once and leave the lease reconciling. An interrupt that arrives during a load or an unload call itself still fails that call, and the lease stays reconciling until a later pass confirms the model is gone. A job that finished before the cancel reached it keeps its answer.
- **Closing the path.** `LeasedImageAdmission.close` tells running batches to stop and does not interrupt them, so the stop cannot reach a server call. Each batch stops at its next step, cancels the backend, waits for it as above and unloads its model. `close` waits for that for up to 15 seconds (a placeholder: a 1-second step, the 10-second wait and a few seconds for an unload that answers promptly), then ends every open job `image-shutdown`. A batch that takes longer goes on as a daemon thread until it ends or the process exits. A batch still loading its model stops only after the load and never reaches its adapter. If the process exits first, the lease stays open and the next process holds it until its model is gone. Requests still queued are withdrawn only when every batch ended, because a running batch may hold the executor's monitor across a server call; nothing grants them after `close`.
- **Outcomes.** Each batch status ends the jobs it did not finish with a fixed code, and nothing retries by itself. `ImageAdmission.usesCatalogArt` is true for any failure, whichever side reported it, and false for a completed or cancelled job.

  | Executor status | Code | When it applies |
  | --- | --- | --- |
  | `DEFERRED` | `image-admission-deferred` | The wait ended; also a wait that ended while still queued for a grant |
  | `DELAYED` | `image-admission-delayed` | The wait ended |
  | `SWAP_FAILED` | `image-admission-swap-failed` | The wait ended |
  | `FELL_BACK` | `image-admission-contention` | At once |
  | `CONTENTION_YIELDED` | `image-admission-yielded` | At once; the backend was told to stop |
  | `INTERRUPTED` | `image-admission-interrupted` | At once; the backend was told to stop |
  | `TIME_CAPPED` | `image-admission-time-capped` | At once; the backend was told to stop |
  | `LOST` | `image-admission-lost` | At once; the backend was told to stop if a job ran |
  | `JOB_FAILED` | `image-admission-job-failed` | At once; also a batch thread interrupted |
  | `LOAD_FAILED` | `image-admission-load-failed` | At once |
  | `COMPLETED` | `image-admission-lost` | Only for a request that joined after the last step |

  `image-admission-unavailable` covers a request that could not be accepted, such as a demand above the whole budget, and `image-shutdown` covers a job still open when the path closes, whichever status its batch ended with.
- **Waiting.** For `DEFERRED`, `DELAYED` and `SWAP_FAILED` the executor asks again itself, so the path never resubmits. With `maxWait` zero, the first such answer gives the fallback and withdraws the request, which is what an image for the scene being read wants. With a longer wait the request stays put back and can still run; when the wait ends it is withdrawn with the last reason as its code. A `maxWait` above `patience` lets contention end it as `FELL_BACK`. Every driver tick also ends the waits that are over and that no batch holds, because a request queued behind a long text lease gets no executor answer at all, and that code is `image-admission-deferred`.
- **Image demand.** `engine.inference.admission.image-gpu-demand-mib` (1 to the GPU budget, default the whole GPU budget) and `image-ram-demand-mib` (0 to the RAM budget, default the whole RAM budget), with the same reasoning as the text demand. Invalid values stop startup without echoing them.
- **Lease model.** A valid checkpoint name is used as it is, and no name becomes `image-current`. A name with characters a lease model may not hold becomes `image-` and a digest, because two checkpoints must not share one lease and its single demand.
- **No image control without the packaged worker.** Unless P21.4-D below adds the worker's, `AdmissionControls` holds only `TEXT`, so with the switch on an image batch ends `LOAD_FAILED` before anything is touched, and the caller shows catalog art. This is deliberate. The `a1111-http` gateway profile refuses the server's checkpoint routes and its VRAM is not coordinated (section 8), so no control can remove its checkpoint, and a control that reported it gone would free its capacity and let a text model load beside it.

Limits and what is not proven:

- Nothing in the application calls `ImageAdmission`, and no game flow chooses catalog art yet (P17.6). So the running application has no image request to admit, and the only runs through a real `runBatch` to a completed image are in tests: with a stand-in control here, and with a double of the worker in P21.4-D below.
- No real server, real adapter call, model, GPU, `nvidia-smi` or PostgreSQL lease store was used. How fast a real backend stops after `cancel`, and whether the 1-, 10- and 15-second waits suit it, is unmeasured. No out-of-memory proof exists.
- The whole-budget default for the image demand has the problem section P21.4-C.1.2.2.1 computes for text: the memory check needs the free reading to cover the demand plus `headroom-mib`, so the default may refuse every load. No working combination of settings has been tried.
- Past the 10-second wait the model is unloaded with the backend possibly still working. A long-running step of a real backend could then hold memory the executor believes is free.
- An unload may take up to 240 status checks, far beyond the 15-second close wait, and after a batch's unload the executor may also bring a text model back. In either case the process can exit before the batch ends, which leaves the lease to the next process.
- The first grant comes from the next tick, up to 1 second later (a placeholder), since an image submission does not force a pass. With `maxWait` zero the request is judged at that tick.
- Batch threads have no fixed limit of their own; the leases that fit the budget bound them, and each lease needs at least 1 MiB of GPU budget by the demand rule. A caller's cancel withdraws its request on one further thread (`inference-image-withdrawal`), so cancels that arrive during a long server call queue there and add no threads.

### P21.4-D packaged image worker behind the lease executor

Implemented in `WorkerSettings`, `WorkerClient`, `WorkerModelControl`, `WorkerImageAdapter` and `WorkerImageConfiguration` in `org.rpgengine.inference.image`, the neutral `ImageModelControl` in `org.rpgengine.inference`, and a small change to `AdmissionConfiguration` (1 November 2026, task open). Tested over real HTTP against `ScriptedImageWorker`, a double written from `docker/image-worker/image_worker.py`, with the real driver, executor and coordinator. No real worker, checkpoint, GPU or database took part.

- **Settings.** `engine.inference.image-worker.url` (unset by default; `http://image-worker:8080` for the packaged service) together with `engine.inference.admission.enabled=true`. With either missing, blank or off, no bean of this step exists and behaviour is unchanged. An address that is not an http or https origin stops startup with a message that names the setting and does not echo the value. Building the beans contacts nothing. The setting is read from Spring's environment; no Compose file sets it, and no launcher command does.
- **Fixed placeholders, not measured:** 4 minutes for a load call, 330 seconds for a generate call, 30 seconds for the connect step and the model list, unload and cancel calls, 8 queued jobs, and 100 ms between repeated cancels.
- **Why a wrapper bean.** `AdmissionConfiguration` finds the text control with a unique lookup of `ModelServerControl`. A second bean of that type would make the lookup fail, so the worker's control reaches it as `ImageModelControl`, a record around the control, and the text path is untouched.
- **Control.** `WorkerModelControl` speaks `POST /v1/load`, `POST /v1/unload` and `GET /v1/models`. Residency comes from the worker's own `loaded` field, and a load or unload must also be confirmed by its own answer: the load's `loaded` or `catalogId` must name the model, and the unload's `loaded` must be null. A success status with any other body fails `control-malformed`. The other codes are `control-busy` (the worker's 409 `busy`), `control-status`, `control-timeout`, `control-unreachable`, `control-too-large`, `control-interrupted` and `control-unsupported` for the slot routes, which only a text control is asked for.
- **Reading `loaded`.** The status of a model is decided by what the worker's answer can and cannot show:

  | The worker's `loaded`, and what this control knows | Status of the model asked about |
  | --- | --- |
  | The file this control loaded for the model, or the model itself as a file name, or anything for `image-current` | `LOADED` |
  | Null, after the worker answered a call from this process | `GONE` |
  | Null, before such an answer, or after a load whose end nobody saw or that answered `busy` | `OTHER`, because `loaded` is null during a load too |
  | Another file: with no lease model on record it may be this model under its catalog ID, and otherwise something replaced the one loaded | `OTHER` |
  | Anything, while this control holds another lease model | `GONE`, which is true of that model |

  `OTHER` is not gone, so the executor unloads. While the worker still works the unload answers `busy`, and the lease stays reconciling with its capacity held until a later pass gets an answer. A control restarted during a load therefore cannot free capacity by mistake.
- **One checkpoint at a time.** The worker replaces its checkpoint on a load, so a second lease must not load under a running first one, which only an image demand below half the budget allows. The control remembers the lease model it holds and refuses another with `control-busy` without calling the worker. That lease ends `LOAD_FAILED`, with nothing to unload.
- **Lease models.** A catalog ID or file name goes to the worker as it is. `image-current` sends no field, so the worker takes its recommended checkpoint, unless something is already resident, which is then used. A name the worker cannot read, such as the `image-` digest of a name a lease model cannot hold, or a file name with a `+`, is refused with 400 and ends `LOAD_FAILED`.
- **Port.** `WorkerImageAdapter` has backend `local-image`. It sends only the worker's fields (`prompt`, `negativePrompt`, `width`, `height`, `steps`, `guidanceScale`, `seed`), because the worker refuses any other. It runs one job at a time on one thread behind a bounded queue, because the generate call lasts as long as the job, so `submit` never waits for the worker. It generates on what is resident: the route takes no checkpoint, and loading belongs to the control. A request naming a checkpoint needs the answer's `checkpoint` or `catalogId` to name it, else `image-wrong-checkpoint`. A sampler other than the worker's `euler-ancestral` fails `image-sampler-unsupported` before any call.
- **Cancelling.** A queued job ends at once. A running job gets `POST /v1/cancel`. That route carries no job ID and stops whatever is generating, so it is sent only while this adapter's own call is in flight, and the next job waits until the cancel has answered. An answer `no-job` means the worker has not started the call, so the cancel is sent again until the call ends. A call that times out is followed by one cancel, because the worker keeps working after a client gives up.
- **Output.** The PNG passes the same `PngCheck` as the `a1111-http` adapter and is reduced to its rendering chunks. `ImageProvenance.serverModelHash` is the SHA-256 in the worker's own provenance record. The rest of that record (versions, VAE, composed prompt hashes, policy) has no field in `ImageProvenance` and is dropped here.
- **Failure codes.** `image-queue-full`, `image-server-busy`, `image-not-loaded`, `image-wrong-checkpoint`, `image-sampler-unsupported`, `image-prompt-too-long`, `image-prompt-refused`, `image-out-of-memory`, `image-generation-failed`, `image-timeout`, `image-unreachable`, `image-status` (any other answer), `image-response-too-large`, `image-malformed`, `image-bad-encoding`, `image-bad-png`, `image-wrong-size`, `image-interrupted` (the worker cancelled a job this adapter did not ask to cancel) and `image-shutdown`. Nothing else the worker says reaches a result.
- **`a1111-http` still gets no control.** The setting names this worker alone, and nothing builds a control from an `a1111-http` adapter or destination. If an owner points the setting at such a server anyway, its answers confirm nothing (a route missing is `control-status`, a body without `loaded` is `control-malformed`), so the batch ends `LOAD_FAILED` and its capacity stays held: the safe side of the mistake, at the cost of that capacity until the setting is fixed.

Limits and what is not proven:

- No real worker has answered. The double follows `image_worker.py` as read, and `tools/container_packaging/test_image_worker.py` pins the same answer shapes on the real class, but no test joins the Java client to that class. No checkpoint has been loaded by this path, and that a real unload frees GPU memory is unmeasured.
- Nothing submits an image: the port and the path have no caller until P17.6, so the batch runs only in tests. The packaged stack was not started with the switch on, and no working combination of settings was tried. The whole-budget image demand may refuse every load against the default headroom, as computed for text above.
- The worker answers a load only when it is done, and the executor holds its monitor across server calls, so a real load stops passes, renewals and the metrics route for as long as it lasts. The 4-minute bound sits under the 5-minute lease, but no real load has tried it.
- An unload's `loaded: null` shows that the worker dropped its pipeline and asked for cached memory back, not that the card reports it free. The executor reads free memory before the next load, not to confirm this unload.
- A worker restarted during a job looks like an empty worker, and the job's own call fails. A process other than the engine calling the worker is outside this design: the network gives it no other peer.
- Lease models and catalog IDs are compared as strings, so a catalog ID and its file name are two leases, and the second is refused while the first runs.

Techniques to evaluate in P21 (none is a promised gain): prompt-cache reuse across turns with stable prefixes; constrained JSON with short `max_tokens` for light tasks; thinking only where it pays; quantized KV cache and flash attention; optional draft-model speculative decoding where spare VRAM exists; a warm-up request after reload; image step and resolution presets; idle-time pre-generation of likely portraits; skipping AI entirely for structured player actions.

Optional [STT/hands-free input](35-speech-input-and-hands-free-play.md) also uses
this shared CPU/RAM/GPU admission; it adds no selected backend or model slot here.
P17.8 must qualify its exact recognition profile and finite audio buffers. Treat
capture/confirmation work as bounded interactive demand alongside interactive
text, without starving canonical work; suspend lower-priority media or disable
recognition when measured headroom/latency cannot be met. TTS readback priority,
echo suppression and any narration interruption require joint QA-45 evidence.

### P21.3-A slot settings, class badges and probes

Implemented in `org.rpgengine.inference.slots` and migration `V27__model_slot_settings.sql`, backend only.

- **Storage.** `inference_slot_setting` holds one row per slot the owner saved (`text.light`, `text.standard`, `text.deliberate`, `image`): backend, model, effort, the class declaration of an endpoint, the class, the last acknowledgement and the last probe. `inference_slot_fallback` holds the ordered fallbacks. Both hold identifiers only, are installation-wide and are not campaign state. A stored text assignment overrides the startup settings of the same slot (`PersistedSlotAssignments`, read from a cache); if the stored rows cannot be read, the slot resolves as unassigned and the task ends `slot-unassigned`, and the startup settings are not used instead.
- **Backends per slot.** Text slots accept `codex`, `claude`, `local`, `openai-compatible` and `anthropic-api`. The `image` slot accepts `local-image`, `a1111-http` and `openai-images` and carries no effort (stored as `none`). Membership names the protocol only; no `claude`, `anthropic-api`, `openai-compatible` or `openai-images` adapter is installed yet, the `local` adapter exists since P21.3-B, the `a1111-http` adapter exists since P21.5-B.2 as a class that nothing constructs yet ([section 8](#8-local-image-worker-profile)), and the `local-image` adapter exists since P21.4-D only behind its address and the admission switch, with nothing selecting it from a slot ([section 10](#p214-d-packaged-image-worker-behind-the-lease-executor)).
- **Class badge.** `codex` and `claude` are `subscription`; `local`, `local-image` and `a1111-http` are `local`; `anthropic-api` and `openai-images` are `metered`; `openai-compatible` takes the owner's `declaredClass` (`local` or `metered`), which no other backend may carry. Each class has a fixed billing code (`free`, `plan`, `per-use`) and privacy code (`this-machine`, `runtime-vendor`, `api-vendor`) that the panel will render.
- **Acknowledgement.** An assignment whose class differs from the slot's current class is refused with 409 `CLASS_ACKNOWLEDGEMENT_REQUIRED` (`from`, `to`) unless `acknowledgeClass` names the new class; the class and time are stored. An unassigned slot counts as `local`, so a first assignment to `subscription` or `metered` needs it and a first `local` one does not. The class of an environment-assigned `openai-compatible` endpoint is unknown, so replacing it always needs it. A change inside one class (for example `codex` to `claude`) needs none.
- **Fallbacks.** At most four, distinct, each on a backend that may serve the slot and in the class of the primary; otherwise 422 `FALLBACK_CLASS_CROSSING` or `FALLBACK_INVALID`. An `openai-compatible` entry counts only beside an `openai-compatible` primary and then takes its declared class. `SlotFallback.select` takes the primary, then the listed entries in order, and ends in `slot-unavailable` when none is available; it never reaches another class and a slot with no entries has no fallback. The profile resolver is offered only the entries on the primary's own backend, because it resolves one backend per task; an entry on another backend of the same class is stored and validated, and no adapter selects it yet.
- **Probes.** `POST /api/v1/models/probe` runs `BackendProbe` for the stored primary assignment and stores the state (`ready`, `failed`, `unreachable`, or `not-run` before any probe), a fixed code, the time and the duration; `GET /api/v1/models/status` shows it and it survives a restart. A changed assignment resets it, and a result that finishes after the assignment changed is discarded. `RuntimeBackendProbe` reads the status of the backend's adapter and the owner's allowlist: a backend with no adapter in this process is `unreachable` with `adapter-not-installed`, a ready adapter is `failed` with `model-not-approved` when the allowlist excludes the pair, `failed` with `model-not-listed` (P21.2-F) when the backend lists its models and its current list lacks the model, and `ready` otherwise. A ready result does not show that the account or server can run the model, and no probe checks the output contract or Italian text yet.

### P21.3-B local text adapter and per-slot session retirement

Implemented in `org.rpgengine.inference.local`, `SlotRoutingTaskPort`, `ScopedSessions.retireSlot`, `SlotSessionRetirement` and migration `V28__session_slot_retirement.sql`. Tested against a scripted HTTP server only, which is a fixture and not a model.

- **Selection.** `engine.inference.local.url` (for the packaged service, `http://models:8080`) installs the adapter. Unset or blank, nothing changes: one task port stays selected. Set, `SlotRoutingTaskPort` becomes the installation's port in front of every adapter. It is an http or https URL with a host and no path, and an invalid value fails startup without being echoed. `./start.sh --with-models` passes `ENGINE_INFERENCE_LOCAL_URL=http://models:8080` to the engine through `compose.models.yaml` (P21.2-F, section 7); a plain start does not pass it, so the adapter stays uninstalled.
- **Optional settings.** `engine.inference.local.queue-capacity` (16, 1–256), `request-timeout` (10s, connect and catalog reads), `reconnect-initial` (1s), `reconnect-max` (30s), `catalog-interval` (5s), `max-sessions` (256, 1–4096), `max-conversation-bytes` (1 MiB, 64 KiB–16 MiB), `temperature` (1.0, 0–2), `top-p` (0.95, above 0 and at most 1) and `top-k` (64, 0–1000). The sampling defaults are the Gemma 4 starting point of section 7 and apply to every model and slot, because no per-slot sampling setting is stored yet.
- **Routing.** Each task goes to the adapter of the backend assigned to its slot, through `fixedQuality` when the owner set it. An unassigned slot ends `slot-unassigned`, and a backend with no adapter ends `slot-backend-mismatch`; both are `FAILED` and send nothing. There is no fallback to another adapter, and the fallback lists of another backend are still not selected. The combined status takes the most usable adapter's state and sums the counts, so the gameplay health shows ready when any adapter is ready, even if a slot's own backend is down. That slot's tasks then end `UNAVAILABLE`. Probes read the status of the slot's own backend.
- **One request.** `POST /v1/chat/completions` carries `model`, `stream: false`, `max_tokens` (1,024, 2,048 or 4,096 for `light`, `standard` or `deliberate`), `temperature`, `top_p`, `top_k`, `reasoning_effort` (the slot's effort), `chat_template_kwargs.enable_thinking` (false only for effort `none`) and a strict `json_schema` `response_format`. No tool is offered. The thinking token budget of section 7 is not sent.
- **Catalog.** `GET /v1/models` is read at startup, every `catalog-interval` while idle and before each task. A pair must list its model there and pass the owner's allowlist when one is set. Effort is not checked against the server. `READY` means only that this list parsed.
- **Validation.** The adapter returns the reply as untrusted text. `ContractRunner` applies the same schema, disclosure and text checks and the same single repair as for any other backend, and a test runs the real runner, scheduler and session registry over the adapter.
- **Fixed result codes.** Server text never reaches a result. `UNAVAILABLE`, nothing ran: `runtime-unreachable`, `model-server-starting`, `model-server-error` or `catalog-malformed` (catalog read), `model-server-busy` (503 on a chat request). `FAILED`: `turn-rejected` (other 4xx), `model-server-error` (5xx), `malformed-completion`, `output-truncated`, `unexpected-finish`, `empty-output`, `tool-call-refused`, `response-too-large` (over 4 MiB). `UNRESOLVED`: `connection-lost`.
- **Conversations.** The chat API keeps no conversation, so the adapter keeps one per logical session, in memory: the instructions and replies of completed tasks, sent again with each request. A restart, a retired session, the `max-sessions` bound or the byte bound starts over, and the next result reports `freshSession`.
- **Cancellation and deadlines.** Closing the connection is the only stop signal this API offers. A cancelled or timed-out request ends `CANCELLED` or `TIMED_OUT` once the exchange is aborted, with no confirmation that the server stopped generating; a later request may wait behind that work. The adapter records no dispatch reference, because an abandoned exchange leaves no conversation at the server to reconcile.
- **Per-slot session retirement.** Saving an assignment that differs from what the slot runs (backend, model, effort, class declaration or fallbacks) publishes `SlotAssignmentChanged`, and every session that ran a task under that slot retires as `SLOT_CHANGED`. Its next task opens a fresh session with a continuity block, and sessions of other slots stay open. A session that ran under two slots is bound to both. Under `fixedQuality`, only the fixed slot's assignment retires anything, and it retires every text session. An identical save retires nothing, a task already running finishes on its old conversation, and the first save over an equal startup setting retires nothing. The `image` slot has no text session. Migration V28 lets `ai_session_record` store the new value.

Compose and launcher selection exist since P21.2-F (section 7). Not built: the model file hash in provenance, per-slot sampling and context parameters, the thinking budget, the API key for `--api-key-file` servers and the other adapters. Not proven: anything about a real server, listed in the [roadmap](16-development-roadmap.md) P21.3 entry.

### P21.3-C.1 gateway container

Implemented in `docker/gateway/` (one standard-library Python file on the pinned image) and the Compose service `gateway`. Tested against a scripted upstream only, which is a fixture and not a provider. Nothing calls it yet.

- **Selection and networks.** Only `--profile gateway` selects it, and no other service depends on it. It joins `gateway`, an internal network whose only other member is the engine, and `gateway_egress`, which nothing else joins. It publishes no port and runs as UID 10002 with a read-only root and no capabilities. It closes connections arriving over the egress network unanswered: the interface with the default route identifies that network, read from `/proc/net/route` at startup. `./start.sh --stop` removes a running gateway and both networks.
- **Inputs.** Two read-only host paths, which `GATEWAY_DESTINATIONS_FILE` and `GATEWAY_KEYS_DIR` can override: the allowlist `.local/gateway/destinations.json` and the keys directory `.local/secrets/gateway/`, one key per file. No launcher command creates either yet, so the owner must create both, readable by UID 10002. A malformed allowlist exits 78 and names a JSON location, never a value. A key file is read once at startup, so a new key needs a restart, and a missing or unusable one makes only its destination answer 503 `key-unavailable`. Compose sets `create_host_path: false`, but Docker Desktop for Windows did not refuse a missing keys directory on the reference host: the container started healthy, which still leaves every keyed destination at `key-unavailable`.
- **Allowlist format.** `{"schema": "rpg-engine.gateway-destinations/1", "max_in_flight": 16, "client_timeout_seconds": 30, "destinations": [...]}`. Each destination has `id`, `url` (an origin only, with no path or credentials) and `path_prefixes`, plus these optional fields: `key` (`file`, `header`, `prefix`), `headers` (fixed and not secret), `plaintext_key`, `max_request_bytes` (default 4 MiB, ceiling 64 MiB), `max_response_bytes` (16 MiB, ceiling 64 MiB), `timeout_seconds` (120, ceiling 900), `max_redirects` (3, ceiling 5), `budget` ([P21.3-C.2](#p213-c2-gateway-budgets)) and `protocol`. The only protocol value is `a1111-http` (P21.5-B.2, [section 8](#8-local-image-worker-profile)): `path_prefixes` may then be left out, and it pins three exact routes with their methods, with default bounds of 1 MiB, 32 MiB, 300 seconds and no redirect. Any other `protocol` value refuses the file. A key over `http://` is refused unless `plaintext_key` is true, for an owner-run LAN server. Unknown or repeated fields refuse the file. Destinations come only from this file.
- **Calls.** `GET|POST /upstream/<id>/<path>[?query]`. `GET /healthz` says only that the process serves. A request names a destination by identifier and can never name a host. A path must fall under a prefix by whole segments, with no dot segment, empty segment or encoded separator.
- **What crosses.** From the engine: `Content-Type`, `Accept`, the body and the query. To the engine: the status, the body of a 2xx answer, `Content-Type` and a well-formed `Retry-After`. No cookie is forwarded or stored, in either direction or across hops.
- **Keys.** A key exists only in the file and in process memory, and it goes only to its destination's origin. Any response holding a loaded key, whole or percent- or base64-encoded, ends in 502 `response-refused`. The body of a non-2xx answer is discarded, because providers echo key fragments in errors; the engine gets the status and `{"code":"upstream-status","status":N}`. A fragment inside a 2xx body cannot be detected.
- **Bounds.** Over `max_request_bytes` is 413 before any contact, and a chunked or missing length is 411. Responses are buffered whole, so over `max_response_bytes` is 502 `response-too-large`, never a truncated success, and nothing streams to the engine. A compressed response is refused (`response-encoded`). One deadline covers all hops and is enforced by severing the socket, so a peer sending one byte at a time cannot outlast it. During connection setup no socket can be severed yet, so a deadline passing then ends the call with 504 `upstream-timeout` once setup returns, before the request or its key is sent. That answer can come late by the time left, at most 10 seconds, for each TCP attempt and the TLS handshake. `client_timeout_seconds` bounds sending one request, and `max_in_flight` bounds relayed calls (503 `gateway-busy`).
- **Redirects.** Followed only to the same scheme, host and port and under the allowed prefixes, at most `max_redirects` times. A POST follows only 307 and 308, which keep its method and body. Otherwise: `redirect-cross-origin`, `redirect-path`, `redirect-limit`, `redirect-method` or `redirect-invalid`. A refused hop contacts nothing.
- **TLS.** Certificate chain and hostname are verified against the image's system store, with TLS 1.2 as the minimum. `upstream-tls` is the failure code.
- **Logs.** One JSON line per call with fixed codes, the allowlisted identifier and counts. There is no path, query, header, body, peer text or exception message.

Limits: name resolution follows the system resolver's own time limit. DNS rebinding is not defended against, because a hostname is trusted to mean what the owner allowlisted. The protocols are not interpreted: nothing here sets a model or parameters or applies retries or quotas. The engine's own `web` network remains an ordinary bridge, because Docker publishes no port from an internal network, so "the engine has no Internet route" ([ADR 0021](adr/0021-inference-backends-and-model-selection.md) decision 6) is not yet true of the packaged stack; this change adds no route to it.

### P21.3-C.2 gateway budgets

Implemented in `docker/gateway/gateway.py` and the Compose volume `gateway_state`. Tested against a scripted upstream only. No adapter calls the gateway yet, so nothing in the engine reads these answers.

- **Slot and unit.** The gateway knows destinations, not slots, so a metered slot is one destination with its own `budget`: `{"daily_calls": N, "monthly_calls": M}`, both required, each from 1 to 1,000,000,000. To cap slots separately, list one destination per slot; they may share an origin and a key file. A cap counts relayed calls per UTC day and UTC calendar month. It does not count tokens or images, because the gateway does not interpret the protocols, so a cap limits spending only as far as calls predict it.
- **What counts.** A call is reserved and written to disk after the request is validated and before any contact, so concurrent calls cannot pass a cap and a killed process cannot forget a call. All redirect hops of a call share one count. A refused request costs nothing: an unknown destination or path, a missing key, a busy gateway, a malformed or oversized request. A call that fails after that point counts, including a timeout, an unreachable destination and a provider error, because the gateway cannot tell whether the provider billed it. Repeated calls during an outage therefore spend the budget. A readiness probe through a metered destination counts too, so a free path such as a model list can have its own destination without a budget.
- **Stop.** A reached cap answers 429 with `{"code":"budget-exhausted-daily"}` or `{"code":"budget-exhausted-monthly"}` and contacts nothing. The monthly code wins when both are reached, because the next day would not help. `Retry-After` gives the seconds until that period ends. A provider's own 429 has the code `upstream-status`, so the two cannot be confused. The gateway has no route from one destination to another, so a capped call moves nowhere; other destinations keep working. Same-class fallback stays the engine's rule (P21.3-A).
- **Time budget per call.** This is the existing `timeout_seconds`, one deadline over all hops ([P21.3-C.1](#p213-c1-gateway-container)), which applies to every destination and ends in 504 `upstream-timeout`. There is no daily or monthly time budget.
- **State.** The counts live in `/var/lib/gateway/budgets.json`, in the named volume `gateway_state`, which only the gateway mounts: the only writable path of the service. The file holds `{"schema": "rpg-engine.gateway-budgets/1", "destinations": {"<id>": {"day": "2026-10-31", "day_calls": 1, "month": "2026-10", "month_calls": 1}}}` and nothing else: no key, path, URL or body. It is replaced whole, so a kill leaves the old or the new content. It survives a restart, a recreated container and `./start.sh --stop`, and it is not part of a database backup.
- **Failure rules.** A missing file means nothing was counted yet, since a first start looks the same. Any other unreadable or malformed file stops every metered destination with 503 `budget-unavailable` and one `budget-state-refused` log line that holds no content, and the file is left in place: resetting it would silently reopen spending. Destinations without a budget and the health path keep working, and never touch the file. To recover, the owner stops the service and removes the file or the volume, which resets the counts. No launcher command does this yet. A write that fails refuses that call with the same code and consumes nothing, so service returns once the write succeeds.
- **Clock and changes.** Only a later period label restarts a count, so a wall clock moved back reopens nothing; the later period's count stays until the clock passes it. A changed cap applies from the next start, against the stored count. Removing a destination's budget forgets its counts on the next write of another destination's count.

Limits: a host power failure can lose the latest counts, because the directory itself is not synced. One process owns the file, so a second gateway on the same volume is not supported. Whether counted calls match a provider's bill is unknown, and no real provider has been metered.

### P21.3-D models panel in Settings

Implemented in `frontend/src/app/models/` and shown inside the Settings screen. It uses the owner routes of P21.3-A unchanged and is tested against a simulated server and a stand-in for the routes, not against the packaged stack.

- **Slots.** One card per slot, in the server's order: the source of the assignment (saved in settings, set at startup or not assigned), backend, model and effort as literal identifiers, the class badge with its billing and privacy lines, the stored acknowledgement, the configured fallbacks and the last probe with its time and duration. An assignment set at startup has no known class for a custom endpoint, and the card says so.
- **Editing.** A form per slot offers the backends the slot family accepts (the lists of section 12), a model, an effort (not for images), the declared class when the backend is `openai-compatible`, and up to four fallbacks. A blank field or an undeclared custom endpoint is explained before anything is sent. The body holds identifiers only; the panel has no field for a key or an address, and nothing in it handles one.
- **Acknowledgement.** A 409 `CLASS_ACKNOWLEDGEMENT_REQUIRED` holds the exact request. The panel names the old and the new class, who would receive the prompts and who bills, and moves focus to that explanation rather than to a confirming button. "Acknowledge and save" repeats the request with `acknowledgeClass` set to the class the server named. Any edit, or Cancel, withdraws the held request; cancelling stores nothing and returns focus to the save button.
- **Probe.** "Check readiness" probes the stored assignment, not the unsaved form, and shows the stored result. The panel states that ready means the backend lists the model, not that the model answers well (section 12, P21.3-A).
- **Admission.** Reads are plain same-origin GETs. Writes carry the CSRF proof from `GET /api/v1/session`; one 403 renews the session once, and a second is shown as "not allowed". Replies are validated field by field, so an inconsistent class badge, probe or slot list is shown as an unreadable reply and nothing partial is rendered.
- **Wording.** Every refusal code of the controller and of `SlotSetting` is a key of the table in `models-messages.ts`, which the repository `localization` check enforces. Unknown codes and probe reasons use one generic sentence and the raw code is never shown. The 82 strings are in English and Italian (catalog 515 units).
- **Keyboard.** Controls are native fields and buttons. A busy button keeps focus and is marked `aria-disabled`. A headless-browser journey with the keyboard alone passed against a stand-in server; no screen reader was used.

Not built: advisor presets, budget display (the gateway's counts are not exposed to the engine), editing a gateway allowlist or key, and any adapter beyond those of earlier tasks. The initial interface bundle is 515 kB, above its 500 kB warning limit.
